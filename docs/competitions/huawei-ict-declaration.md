## 一、技术选型说明

SeaSight 面向县域海漂垃圾治理的"感知—决策—执行"闭环。选型时对齐了三条约束：
**边缘算力受限**、**政务侧数据不出域**、**决策过程必须可审计**。
华为技术栈在这三条上与项目需求同向：

- **边缘与模型服务分层** → 检测推理做成独立服务，加速后端可替换（昇腾 Atlas / CANN 路径）；
- **模型调用协议标准化** → 规划器采用 OpenAI 兼容客户端，可指向 ModelArts 在线服务；
- **能力以标准协议暴露** → 领域认知能力以 MCP（Model Context Protocol）工具面 + Skills 形式对外，
  由华为 ModelEngine Nexent 承载编排。

## 三、架构就绪的技术纽带（虚线）

以下三项**不写"已适配"，只写"架构与配置已就绪、待验证"**。

### 3.1 昇腾 Atlas + CANN：推理后端可替换

- 检测推理服务在启动时自动探测可用执行提供者，按 GPU 优先、CPU 兜底装配，
  并把实际生效的 provider 暴露在健康检查里；
- 模型加载失败时降级为确定性 stub 模式且不阻断服务启动，保证平台可独立联调；
- ONNX 导出脚本已按静态形状、固定 batch、简化图的方式导出，具备进入 ATC 转换的前置条件。

**接入路径与风险点**见 `huawei-ascend-modelarts.md` §一（含 ATC 命令示例、
`CANNExecutionProvider` 装载方式、Atlas 边缘盒拓扑、检测头算子风险登记）。
**未在昇腾硬件上实测。**

### 3.2 ModelArts 模型服务：配置级兼容

- 规划器为 OpenAI Chat Completions 兼容客户端，服务地址、密钥、模型名三项均通过环境变量注入；
- 模型不可用 / 超时 / 输出不合 schema / 输出越权四类情况下，
  规划器回落到确定性规则规划器，并返回结构化回落原因（**该行为已实现且有单元测试**）。

**配置示例与最小验证步骤**见 `huawei-ascend-modelarts.md` §二。**未实际调用过 ModelArts。**

### 3.3 鲲鹏 arm64 / openGauss：迁移可行性

- **鲲鹏**：基础镜像为官方多架构镜像，依赖链无 x86 专有编译产物，
  数据库 / 缓存 / 消息中间件均有 arm64 官方镜像。**未在鲲鹏服务器上执行过编排验证。**
- **openGauss**：对象关系映射层为 SQLAlchemy、迁移工具为 Alembic，具备方言抽象；
  但**当前初始 schema 依赖 PostGIS 空间扩展**（`backend/db/init/01_schema.sql`，
  含 4 处 `geometry(Point, 4326)` 与网格聚合查询），openGauss 不提供 PostGIS。
  因此该项的准确表述是：**可作为替代方向评估；空间数据层需先行改造；未实测。**

## 六、答辩三问标准话术

### 问 1：「华为技术用了哪些？」

> ModelEngine Nexent 是实际集成的一条：领域认知能力以 MCP 工具面暴露，
> 默认 21 个只读工具、开启写入开关后 32 个，另有 5 个 Skills 模板，
> 出站令牌自动刷新，已通过协议级验收，这条命令可以在代码仓库里复现。
> 昇腾、ModelArts、鲲鹏这三条是架构与配置层面已经就绪的纽带——
> 检测推理的后端可替换、规划器的服务地址可切换、容器基础镜像是多架构的，
> 但都还没有在目标硬件上实测，所以材料里写的是"待验证"而不是"已适配"。

### 问 2：「昇腾跑过吗？」

> 没有跑过，这一点我们不绕。我们交付的是**可迁移的架构与接入说明**：
> ONNX 导出已经按静态形状和固定 batch 准备，ATC 转换命令、
> `CANNExecutionProvider` 的装载方式、Atlas 边缘盒的部署拓扑都已写成材料，
> 连检测头算子在跨平台转换中的风险点也登记了。
> 昇腾验证是我们下一步的产教合作计划，不是已经完成的工作。

### 问 3：「换成华为云行不行？」

> 模型调用这一层可以。规划器是 OpenAI 兼容客户端，
> 地址、密钥、模型名三项都是环境变量，指向 ModelArts 在线服务是配置动作，
> 不涉及改代码。而且回落护栏已经实现并有单元测试：
> 模型不可用、超时、输出不合格式或越权时，系统回落到确定性规则规划器，
> 并给出结构化的回落原因——现场可以把地址指到一个不可达的地方，
> 系统照样出派单方案。至于数据库换成 openGauss，我们不会说"改个连接串就行"：
> 当前 schema 用了 PostGIS 做空间聚合，openGauss 不提供这个扩展，
> 空间数据层要先改造，这是我们评估过的结论。
