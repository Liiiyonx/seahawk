一、设计背景
我国近岸海域（尤其是养殖业密集的县域岸段）长期受海漂垃圾影响：泡沫浮球碎片、废旧渔具、饵料袋等漂浮物威胁养殖安全与海岸景观。基层治理中沉淀了大量政策文件、巡查台账、事件记录与处置工单，但这些资产分散异构、难以被决策直接调用——治理决策长期依赖个人经验，说不清“依据哪份文件、哪个版本、哪条记录”。
与此同时，决策自动化面临三重现实约束：其一，领域语料稀缺，无法依赖大规模标注冷启动知识库；其二，治理决策必须可追责，不接受黑箱结论；其三，模型输出不可全信，越权操作必须能被拦住。传统规则引擎难以应对动态场景，单一 AI 模型又缺乏工具调用与多步推理能力。
本项目以华为 ModelEngine Nexent 为基座，构建面向县域海洋环境治理的可进化决策智能体“探海灵眸 Oceanus”。设计目标可以概括为：让智能体“看得见新东西、说得清理由、被管得住、事后查得到、越用越聪明”——前四点是决策可用的底线，最后一点是“可进化”的落点。
二、应用场景
核心场景是养殖区海漂垃圾治理的完整决策闭环：岸基摄像头感知发现 → 事件生成与研判（智能体） → 策略守卫校验 → 多角色人工审批 → 平台派单 → 执行端作业（水面打捞机器人 / 岸基机械臂，均为可替换的 MQTT 作业端） → 作业回执 → 复盘进化。智能体在闭环中承担研判、规划、调度、复盘四个决策角色。
“可进化”落在三个层面。经验进化：每次运行终态自动复盘，提炼结构化经验（例如“某类事件在当前时段常无可用执行端”），同类事件规划期自动引用，置信度用贝叶斯后验校准——引用与确认分别计数、16 次确认封顶 0.95、永不到 1.0，因为只会上涨的置信度不是置信度。知识进化：本体以版本链演进，新资产版本进入新一轮候选抽取，人工审核后发布新版本，增量抽取较全量重抽节省 63.19% 耗时。策略进化：决策证据链同时固化资产版本、本体版本与策略版本，策略调整后历史决策仍可按当时口径回放。
与国内外同类方案对比：市面海漂垃圾治理方案以单机清洁机器人产品为主（WasteShark、Clearbot 等），本项目把战场从“看得见、捞得着”推进到“可追责、可复核”的治理决策层——增量在决策与数据资产层，不在单机感知硬件：

一、总体架构：认知—编排—执行三层
认知层（Oceanus 知识域）：多模态资产版本化登记 → 低资源半自动本体构建（候选抽取 → 人工审核 → 发布）→ 跨文档多跳检索（带关系路径与跳数）→ 决策证据链（按顺序固化证据、引用到资产版本）。领域语料稀缺场景下不依赖标注训练，用确定性的词频/共现候选算法加人工审核冷启动，全过程可解释、可审计。
编排层（Nexent Agent）：接入 DeepSeek 大模型，通过 MCP 协议调用 Oceanus 工具面，按 Skill 工作流模板组织“先查什么、再算什么、何时停止”。Skill 以自然语言固化触发条件、工具顺序与停止条件，是可跨行业复用的业务逻辑模板（替换本体与资产源即可迁移）。
执行层（Oceanus 业务系统）：角色权限（四类角色，服务端签名令牌）、辖区过滤、审批、幂等与审计；执行末端可插拔（岸基设备、水面机器人、机械臂统一走派单链路）。关键分工：Nexent 负责编排与推理，Oceanus 后端负责权限与事实——工具返回后端真实数据，业务失败被转换为工具错误返回给模型，不会伪装成成功数据。

二、决策运行时（Runtime）
单次决策的完整生命周期：任务规划 → MCP 工具调用 → 策略守卫校验（敏感工具、角色越权、步数预算） → 多角色人工审批（operator 申请、admin/approver 决策） → 执行 → 全程轨迹审计与回放。
工程可靠性：运行时持久化——等待审批的运行落库后，全新进程可续跑并完成派单闭环；并发幂等——同一幂等键只创建一次运行，重复触发复用；乐观锁冲突检测——旧版本保存被拒绝且不覆盖原数据。模型侧非法 JSON、超时、越权一律回退确定性规则规划器（source=rule_fallback），决策链路不因模型故障中断。

) -> float:
"""Beta 后验均值：`(α·prior + successes) / (α + trials)`。
无观测时恒等于先验；成功使置信度上升、失败使它下降
——这是与「只增不减的计数递增」的本质区别。
"""
if not 0.0 <= prior <= 1.0:
raise ValueError(f"prior 必须在 [0,1]：{prior}")
if prior_strength <= 0:
raise ValueError(f"prior_strength 必须为正：{prior_strength}")
if successes < 0 or trials < successes:
raise ValueError(f"非法观测计数：successes={successes}, trials={trials}")
return (prior_strength * prior + successes) / (prior_strength + trials)
解读：无观测时恒等于先验；经验被引用后的真实成功使置信度上升、失败使它下降——这与“只增不减的计数递增”有本质区别，是经验进化不会被自我强化的关键设计。
