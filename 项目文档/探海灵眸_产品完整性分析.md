## 0. 一句话结论

**工程完成度远超产品完成度，而产品完成度又远超"感知端"完成度。**

截至 2026-09-18，平台侧（派单引擎、状态机、权限、报表、契约校验与测试门禁）已经形成完整的软件闭环；但感知链路当时仍缺少独立数据与可报告精度。到 2026-09-22，OpenCV 传统视觉、Agent E1 运行时、Agent E2 真实状态软件集成验收和 1061 项全量测试已经补齐工程底座，真实海域精度、硬件和外部商业证据仍是下一阶段缺口。

**去掉机器人本体后的独立参赛结论：可以作为一个完整的智能体软件项目参赛。** 建议名称使用“海漂垃圾治理决策与调度智能体软件”，定位为事件理解、设备与空间工具调用、计划生成、策略校验、人工审批、派单执行、结果验证、轨迹回放和离线评测的完整 Agent 应用；机器人仅作为可替换的 MQTT 作业端或数字孪生。该定位不需要真实船体即可完成主链路演示，但不能据此宣称真实机器人、真实海域或生产级运行已经完成。

 completeness 的短板不是"代码没写完"，而是**三处"看起来完成、实际是空的"**，以及**一处"压根没设计"**（商业化）。

## 3. 致命缺口 Top 5（按对"评委说服力 / 真实可用性"的杀伤力排序）

### 🥇 缺口 1：识别是空心的——整条链的源头没有真东西
- 现状：`ml/configs/seasight.yaml` 的 stats 全 0（train_images: 0 / instances 全 0）；`edge/main.py` 未实现；AI 服务 `Detector.load()` 找不到模型就静默降级 stub，用 MD5 造 1~4 个框。
- 杀伤力：**评委只要问一句"你这检测结果是怎么出来的"，演示就穿帮**。而且这是"感知—决策—执行"故事的第一环，塌了后面全塌。
- 复杂度：走 YOLO 路线 = 采集 + 标注 + 训练 + 导出 + 边缘部署，至少需要 3~4 周且依赖天气与出海。

### 🥈 缺口 2：报表数据是死的——"数据价值"承诺没兑现
- 现状：`t_report_daily` 只由 `02_seed.sql` 灌入，**代码中没有任何定时聚合任务**。系统跑一年报表也不动。
- 杀伤力：项目最差异化的卖点是"数据价值（热力图、量化报表、溯源分析）"，**而报表恰恰是不涨的**。这是"演示型系统"最典型的破绽。
- 修复成本：**低**（一个定时任务 + 一条 UPSERT，半天）。

### 🥉 缺口 3：权限是摆设——交付给政府部门是硬伤
- 现状：三层角色模型 + `township_scope` + `can_write` 都在，但无登录页、无 token 写入、无路由守卫；`require_operator` 依赖零引用。
- 杀伤力：政务场景里"谁能改工单、谁能看哪个乡镇的数据"是**刚需**，不是加分项。目前前端任何人都能点"完成工单"。
- 修复成本：**中**（登录页 + store + 路由守卫 + 按角色隐藏操作，2~3 天）。

### 缺口 4：没有导出和通知——"能用"和"好看"的分界线
- 现状：无 Excel/PDF 导出、无微信/短信/邮件/站内通知，告警只在大屏滚。
- 杀伤力：真实工作流里，乡镇操作员**不会一直盯着大屏**，告警必须推到人；周报月报必须能导出交差。
- 修复成本：**低**（导出 1 天，站内信 + 企业微信机器人 1 天）。

### 缺口 5：商业化完全空白——创业大赛的必答题
- 现状：4501 行文档里没有一个字讲**谁付钱、付多少、成本多少**。
- 杀伤力：这是"创新创业大赛"而不是"程序设计竞赛"，商业闭环缺失会直接被评委归为"学生作业"。
- 修复成本：**低**（一页纸：按年服务费 / 按清理量 / 设备销售三种模式 + 成本结构 + 按 F-05 口径引用 WasteShark 约 2.36 万美元起售价）。

## 4. 识别方案评估：改用 OpenCV

### 4.1 为什么现在必须换

YOLO 路线的**前置依赖是数据集**，而数据集 stats 是 0。这条路的真实代价是：

| 环节 | 现实约束 |
| --- | --- |
| 采集 | 要出海/蹲码头，受天气与渔汛影响，学生团队排期不可控 |
| 标注 | 2000 张 × 4 类，小目标密集，人工 3~5 天起 |
| 训练 | 两阶段、调参、导出 ONNX，需要 GPU |
| 部署 | 边缘盒（RK3588/Jetson）适配 RKNN/TensorRT |
| **总工期** | **3~4 周，且任何一环卡住全线停摆** |

而 OpenCV 传统视觉方案的**前置依赖是 0**——不需要一张标注图，今天写明天就能出真实检测结果。

### 4.2 三个方案对比

| | 方案 A：纯 OpenCV | 方案 B：OpenCV 提候选 + 轻量分类器 | 方案 C：继续 YOLO |
| --- | --- | --- | --- |
| 数据依赖 | **0 张** | 几百张（只标分类，不标框，成本 1/5） | 2000 张全标框 |
| 工期 | **2~3 天** | 1.5~2 周 | 3~4 周 |
| 预期召回（海上小目标，E0 工程预测） | 中（60~75%） | 中高（75~85%） | 高（85%+，数据足够时） |
| 误报 | **高**（靠时序校验压制） | 中 | 低 |
| 可解释性 | **强**（阈值、规则肉眼可调，评委现场演示可互动） | 中 | 弱（黑盒） |
| 硬件要求 | **CPU 可跑**，树莓派/RK3588 都行 | CPU 可跑 | 需要 NPU/GPU |
| 上限 | 低，天会花板明显 | 中 | 高 |

### 4.3 推荐：方案 A（纯 OpenCV）打底，接口留好换 B/C 的口子

**理由（产品判断，不是技术偏好）：**

1. **它把"空心"变成"实心"，且是这次演示周期内唯一能做到的。** 评委看到的是"摄像头对着水槽/码头，真的框出了泡沫碎片并派了单"，而不是"模拟器发的假报文"。这一条的说服力提升，远大于 mAP 从 70% 到 85%。
2. **误报正是这个项目的强项所在。** `TemporalValidator`（8fps 抽帧、15 帧窗口、min_hits=3、中心位移 <60px、IoU>0.25、90 秒冷却）天生就是为"低质量检测器 + 时序确认"设计的。当前合成海面链路为 599 条输入检测、3 个确认事件，**时序抑制率 76%**；定义为“被过滤检测数 / 输入检测数”，不是模型精度。
3. **可解释性是比赛的加分项。** 现场问"白色阈值多少"能当场拖动滑块演示，比"我们训了个模型"更有说服力，也更符合"低成本国产化路线"的叙事。
4. **成本叙事自洽。** OpenCV 纯 CPU 有利于降低边缘计算成本；对外比较只能引用 F-05 的外部报价及折算假设，仍需供应商询价证明国产化成本优势。

**代价要诚实写进答辩：**
- 强反光、雨天、夜间会显著退化 → 用"作业时段（白天平潮）"作为产品约束写进方案，而不是藏着。
- `plastic` 类（颜色杂、形状不定）准确率会明显低于 `foam` → 产品线定位上，主攻 **foam（EPS 泡沫浮球碎片）**，这也是文档里写的"当地最突出、治理优先级最高"的类别。**聚焦一个类别做到能看，比四个类别都半吊子强。**

### 4.4 落地设计（与现有契约零改造对接）

现有 AI 服务契约：
```json
{"detections": [{"class": "foam", "confidence": 0.72, "bbox": [x1,y1,x2,y2]}],
 "aggregate": {"main_class": "foam", "count": 1, "max_confidence": 0.72}}
```
OpenCV 检测器只要产出**同样结构**，下游（时序校验 → MQTT 上报 → 派单 → 大屏）**一行都不用改**。

管线设计：
```
帧 → ROI 掩膜（排除天空/岸线/固定物）
   → 背景建模（KNN/MOG2，海浪周期运动被建模为背景）
   → 帧差 + 形态学开闭（去波光噪点）
   → 轮廓筛选（面积 40~3000px²、长宽比、填充度、凸性）
   → 特征提取（HSV 亮度/饱和度、Lab、形状、纹理方差、运动一致性）
   → 规则分类 foam / plastic / fishing_gear / other
   → 伪置信度（特征距离映射，阈值对齐现有 0.45）
   → TemporalValidator（复用，不改）
   → MQTT 上报（契约不变）
```

模块位置：`edge/detector/`（检测器 + 配置 + 标定脚本 + 测试），`edge/main.py` 作为真实边缘入口（RTSP/视频文件/摄像头三选一）。
