# 数据需求与脱敏规则说明(给数据提供方看的一页纸)

> 目的:让对方一眼看懂"我们要哪几列、删哪几列、数据去哪"。

## 我们需要的字段(全部为统计字段,无个人属性)

| 字段 | 为什么需要 |
| --- | --- |
| 日期 | 时间趋势、月度聚合 |
| 乡镇/区域/点位(到村或岸段即可) | 区域热力、派单演示 |
| 垃圾类别(泡沫/塑料/渔具/其他…) | 类别结构、本体构建 |
| 数量/重量 | 量化报表 |
| 处置方式(打捞/岸基分拣/转运…) | 处置闭环链路 |

## 我们会删除/替换的字段(拿到后第一时间处理)

| 字段 | 处理方式 |
| --- | --- |
| 姓名、电话、身份证号 | **整列删除** |
| 精确住址 | **删除**,仅保留乡镇级 |
| 船号、车牌 | **删除或打码** |
| 照片中人脸 | **打码** |
| 操作/巡查人员姓名 | 替换为角色代称("值班研判员 A") |

## 数据去向

- 原始文件:仅存团队本地,不入仓库、不上网
- 脱敏副本:进入参赛作品的演示数据库,用于知识检索与报表演示
- 比赛材料中标注:"数据来源:«提供方名称»真实运营台账(已脱敏)"

## 最小可用规模

任意一个乡镇、近 3–6 个月、几百行即可支撑完整评测;有多个月/多个乡镇更好,不作硬性要求。
