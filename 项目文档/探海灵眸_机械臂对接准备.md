# 探海灵眸 机械臂对接准备

> 适用范围：真机械臂到货前，先把平台侧账号、设备注册、协议与自测做完；机械臂
> 一到，只需为这台机械臂补一个 `ArmDriver` 驱动适配器，桥接层和平台契约
> 不用再改，就能走「感知 → 派单 → 拾取 → 回传」闭环。
>
> 证据口径：真机械臂 + 仿真海面 / 受控实验 = **E2**；感知精度仍为
> `not_evaluated`；「链路跑通」不等于「识别准了」。
>
> 资料逐项结论见《机械臂与底盘资料适用性清单》。

## 一、现在就能做的准备

| 优先级 | 事项 | 完成标准 |
| --- | --- | --- |
| P0 | EMQX 机器人账号与 ACL | `robot_device` 能订阅任务、发布 ACK / progress / 遥测 |
| P0 | `t_device` 注册机械臂 | 设备类型仍为 `robot`，页面能看到且可被派单 |
| P1 | 机械臂桥接层骨架（已实现） | 桥接层在 `edge/arm_bridge/`，`--dry-run` 可跑通派单闭环；到货后只补驱动 |
| P1 | 无机械臂就绪自测（已实现） | 桥接层自测已验证报文闭环；平台工单闭环由 `make smoke` / 仿真页验证 |
| P1 | 幻尔树莓派总线舵机驱动适配（已实现） | `HiwonderBusServoArmDriver` 已注册为 `hiwonder_bus_servo`；到货后放 SDK、填示教序列即可 |
| P2 | 到货后联调与证据包 | 录像、报文日志、前后照片，证据等级标 E2 |

## 二、平台侧前置

### 2.1 EMQX 机器人账号

开发环境 `deploy/emqx/bootstrap.csv` 已内置 `robot_device` 账号，密码为开发
占位值 `CHANGE_ME`。真机联调前必须替换：

```dotenv
MQTT_ROBOT_USERNAME=robot_device
MQTT_ROBOT_PASSWORD=<强密码>
```

生产环境在 `.env.production` 增加这两项后执行 `make prod-mqtt-bootstrap`。
已跑起来的 EMQX 不会因改文件自动生效：

- 开发环境：删除 `emqx_data` 卷后 `docker compose up -d` 重新导入。
- 生产环境：进 EMQX Dashboard 在线补账号与 ACL，或按部署文档操作。

机器人账号 ACL（原型期共用账号，生产二期应切到每台设备独立账号）：

| 方向 | 主题 |
| --- | --- |
| 订阅 | `robot/{robot_id}/task`、`robot/{robot_id}/cmd` |
| 发布 | `robot/{robot_id}/cmd/ack`、`robot/{robot_id}/task/progress` |
| 发布 | `marine/{site}/{robot_id}/telemetry`、`marine/{site}/{robot_id}/status` |
| 兜底 | 其余全部 `deny` |

注意：真机遥测必须走 `marine/{site}/{robot_id}/telemetry`。后端当前只订阅
`marine/+/+/telemetry`，不消费 `robot/+/telemetry`。

### 2.2 设备注册

机械臂沿用现有 `robot` 设备类型，不新增 `arm` 枚举，否则要同步改模型、种子
数据与 ACL：

```sql
INSERT INTO t_device (device_id, device_type, name, location, status, last_heartbeat, meta)
VALUES (
  'RBT-ARM-01',
  'robot',
  '机械臂执行末端',
  ST_SetSRID(ST_MakePoint(119.6540, 26.3870), 4326),
  'online',
  now(),
  '{"hull":"机械臂原型","battery":100,"bins":{"foam":0.0,"plastic":0.0,"mixed":0.0}}'
)
ON CONFLICT (device_id) DO NOTHING;
```

`bins` 是平台派单判断仓容的字段。机械臂若没有三仓概念，先填 0，页面会显示
空仓；不要为了演示效果填假仓容。

## 三、协议清单

平台与机械臂之间只约定 MQTT 报文，不要求机械臂 SDK 直接懂 Oceanus 协议。
桥接层负责转换。

### 3.1 订阅派单 `robot/{robot_id}/task`

平台下发的任务带冻结信封，桥接层至少使用 `command_id / device_id / seq /
action / params`：

```json
{
  "command_id": "cmd_tsk_20260928_a1b2c3",
  "device_id": "RBT-ARM-01",
  "seq": 1,
  "issued_at": 1758230400.0,
  "expires_at": 1758230430.0,
  "action": "dispatch",
  "params": {
    "task_id": "tsk_20260928_a1b2c3",
    "target": { "lng": 119.6531, "lat": 26.3867 },
    "priority": 1
  }
}
```

### 3.2 回执 `robot/{robot_id}/cmd/ack`

收到任务后立即回执，`command_id` 原样返回：

```json
{
  "ack_id": "ack_arm_0001",
  "command_id": "cmd_tsk_20260928_a1b2c3",
  "device_id": "RBT-ARM-01",
  "seq": 1,
  "received_at": 1758230401.0,
  "accepted": true,
  "reason": "dispatched",
  "mode": "navigating"
}
```

平台按 `command_id` 幂等去重，QoS1 重投不会重复推进。

### 3.3 作业回传 `robot/{robot_id}/task/progress`

状态变化时上报，不要高频刷：

```json
{
  "task_id": "tsk_20260928_a1b2c3",
  "robot_id": "RBT-ARM-01",
  "status": "done",
  "progress": 1.0,
  "collected_weight": 0.05,
  "review_result": "confirmed",
  "evidence_url": "http://minio:9000/events/tasks/tsk_20260928_a1b2c3_after.jpg",
  "bins_after": { "foam": 0.1, "plastic": 0.0, "mixed": 0.0 },
  "ts": "2026-09-28T10:30:00+08:00"
}
```

`status` 取值 `navigating / collecting / returning / done`，`review_result`
取值 `confirmed / not_found / recheck`。

### 3.4 遥测 `marine/{site}/{robot_id}/telemetry`

```json
{
  "device_id": "RBT-ARM-01",
  "device_type": "robot",
  "timestamp": "2026-09-28T10:31:00+08:00",
  "location": { "lng": 119.6531, "lat": 26.3867 },
  "status": "collecting",
  "battery": 100,
  "bins": { "foam": 0.1, "plastic": 0.0, "mixed": 0.0 },
  "task_id": "tsk_20260928_a1b2c3",
  "speed": 0,
  "heading": 0
}
```

平台用遥测更新设备在线状态、电量、仓容与轨迹，派单引擎直接读这些字段。

## 四、桥接层（已实现）

桥接层已落地在 `edge/arm_bridge/`，职责固定为三件事：

1. 连接 EMQX，订阅 `robot/{robot_id}/task` 与 `robot/{robot_id}/cmd`。
2. 收到 `action=dispatch` 后调用 `ArmDriver.pick()` 执行拾取动作。
3. 把驱动结果翻译成 ACK、progress 与 telemetry 报文。

| 文件 | 职责 |
| --- | --- |
| `bridge.py` | MQTT 契约层：订阅、ACK、progress、telemetry、幂等、过期拒绝 |
| `drivers.py` | `ArmDriver` 协议 + `SimulatedArmDriver` / `HttpArmDriver` / `HiwonderBusServoArmDriver` |
| `mqtt_transport.py` | paho-mqtt 真实传输，支持 LWT |
| `main.py` | 入口：`--dry-run` 自测或连接真实 broker |
| `config.yaml` | 设备、站点、MQTT、驱动配置 |
| `test_bridge.py` | 内存 transport 全链路测试 |

机械臂 SDK 的串口 / CAN / HTTP 接口差异全部隔离在 `ArmDriver`；新增任意型号
机械臂时，平台侧契约与桥接层主体不用改。

## 五、无机械臂就绪自测

先做无硬件自测（不需要 broker、不需要机械臂）：

```bash
.\.venv-analysis\Scripts\python.exe -m pytest edge\arm_bridge -q
.\.venv-analysis\Scripts\python.exe edge\arm_bridge\main.py --config edge\arm_bridge\config.yaml --dry-run
```

预期按顺序出现：ACK（`accepted=true, mode=navigating`）→ `collecting` →
`marine/.../telemetry` → `done` → 末次遥测 `idle`。接着再跑静态检查与现有闭环：

```bash
make check-contract
make smoke
```

再用平台工单仿真页把任务从 `assigned` 走到 `done`，确认前端与 HTTP 契约
稳定。最后手动发一条 ACK，验证 EMQX ACL 真的放行：

```bash
mosquitto_pub -h localhost -p 1883 \
  -u robot_device -P CHANGE_ME \
  -t 'robot/RBT-ARM-01/cmd/ack' -q 1 \
  -m '{"command_id":"cmd_<task_id>","device_id":"RBT-ARM-01","seq":1,"received_at":1758230401.0,"accepted":true,"mode":"navigating"}'
```

`command_id` 必须与平台真实任务一致，否则身份三重校验会整条拒绝。仿真页与
手动回包只证明协议与权限，不证明物理拾取。

## 六、到货后联调

1. 真机到货后，先在 `edge/arm_bridge/drivers.py` 为这台机械臂实现
   `ArmDriver`。HTTP SDK 可直接复用 `HttpArmDriver`；串口 / CAN 写一个
   新适配器即可，桥接契约不变。
2. 用 `--dry-run` 先验证新驱动能被桥接层正确调用。
3. 桥接进程连接 EMQX（凭据 `robot_device`，生产按每台设备独立账号），
   用手工触发一条任务，确认 ACK 被平台接受。
4. 做一次完整拾取：平台派单 → 桥接层回 ACK → 机械臂动作 → progress 回传 →
   工单 `done`。
5. 记录证据包。

幻尔树莓派总线舵机机械臂的专用步骤：

1. 把商家资料里的 `ros_robot_controller_sdk.py` 复制到树莓派上
   `edge/arm_bridge/` 同目录（`pip install pyserial`）。驱动延迟导入 SDK，
   缺依赖时只影响物理动作，不影响桥接层启动与自检。
2. 用商家「案例5 示教记录」把「接近 → 抓取 → 抬起 → 回位」录成舵机位置
   序列，填 `edge/arm_bridge/config.yaml` 的
   `driver.vendors.hiwonder_bus_servo.pick_sequence`；也可以先在树莓派上
   跑 `edge/arm_bridge/tools/teach_hiwonder_sequence.py` 录每一步的位置，
   输出 JSON 后配置 `pick_sequence_file`（两种方式二选一，同时出现会
   报错）。最后把 `driver.backend` 改为 `hiwonder_bus_servo`。
3. 先跑配置自检与无硬件协议自测：

   ```bash
   .\.venv-analysis\Scripts\python.exe edge\arm_bridge\main.py \
     --config edge\arm_bridge\config.yaml --check-driver --driver hiwonder_bus_servo
   .\.venv-analysis\Scripts\python.exe edge\arm_bridge\main.py \
     --config edge\arm_bridge\config.yaml --dry-run
   ```

4. 再接真实 broker 跑「派单 → ACK → 机械臂示教动作 → progress done」。
   平台派单的 GPS `target` 只作任务上下文；真机拾取按 `pick_sequence` 示教
   动作执行，不把经纬度当关节角计算。`review_result` 默认 `recheck`，只有
   人工核对拾取前后照片后才改成 `confirmed`。

麦轮底盘的总线电机接口（`set_motor_speed / set_motor_duty`）已确认可用，
但桥接协议当前只有拾取与机械臂控制语义。需要「平台指令驱动底盘移动」时，
新增一个底盘 `Driver` 和对应动作即可，桥接层结构不变。

## 七、证据包与口径

证据包至少包含：

- 日期、地点、机械臂型号与固件版本；
- 演示录像（从派单到拾取完成）；
- MQTT 报文日志（task / ack / progress / telemetry）；
- 平台工单截图（`assigned → navigating → collecting → done`）；
- 拾取前后照片；
- 证据等级标注：**E2（受控实验）**。

口径红线：

- 真机械臂 + 仿真海面 / 受控实验只能标 E2，不得写成 E3（现场验证）或
  E4（商业验证）。
- 感知精度保持 `not_evaluated`，不把「链路跑通」写成「识别准了」。
- 演示措辞用「本镜头不构成现场验收」，不写「已部署」「真实海域」等
  无凭证表述。

这套对接对连江赛和华为 ICT 赛都是加分项：连江讲软硬结合的执行链路，华为赛
讲真实设备联动的治理智能体。口径统一为受控实验 E2，两边共用一份证据。
