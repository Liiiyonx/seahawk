## 0. 一句话定位

> **主定位语（默认对外，已可辩护）：**
> **面向养殖区海漂垃圾的可审计治理智能体。**
>
> **可选强化语**（仅在材料中同时给出检索日期、检索式与边界时可用，见附录 A）：
> 「国内首个**以决策证据链与人工审批为核心**的养殖区海漂垃圾治理智能体」。

主语是**治理智能体**，不是"系统"。三个限定词缺一不可：

| 限定词 | 含义 | 为什么必须带着 |
| --- | --- | --- |
| 养殖区 | 场景边界：中国东南沿海养殖区（EPS 泡沫浮球碎片、废旧渔具、饵料袋） | 不带就变成"通用水面垃圾"，和所有竞品无法区分 |
| 海漂垃圾 | 对象边界：水面漂浮的固体垃圾 | 不含水下、滩涂、大气微塑料 |
| **可审计** | 能力边界：每一次决策有策略版本、有审批人、有证据链、可回放 | **这是本项目唯一别人不好抄的地方** |

### 0.1 ★★ 「国内首个」已核查：**原措辞不可用**

2026-10-08 完成前置检索（检索式与反例见附录 A）。结论：**「国内首个面向养殖区海漂垃圾的可审计治理智能体」按字面不可辩护** ——
每一个限定成分都已被现有工作单独占据，且「养殖区 + 海漂垃圾 + AI 闭环」组合在 **2020 年福州**就已由官方宣示。

**因此对外材料必须改为**：
- 默认：**面向养殖区海漂垃圾的可审计治理智能体**（不含"首个"）；
- 需要"首个"的冲击力时，只用收窄版：**国内首个以「决策证据链 + 人工审批」为核心的养殖区海漂垃圾治理智能体**，
  并同时写出检索日期与检索式。

### 0.2 正确的差异化叙事：**把战场从"看得见"挪到"可追责、可复核"**

反例中的福州 2020、宁德霞浦 2026、青岛"灵龙"、深圳"深 i 测"、台州"蓝色循环"，
强项都在**感知层与追踪层**。本项目**主动承认它们是前序工作**，增量只在**决策层**：

| 前序工作在做的事 | 本项目增量 |
| --- | --- |
| 识别垃圾、发现事件（福州 2020；霞浦 2026） | —— 本项目不主张这是创新 |
| 全生命周期可追溯、区块链存证（台州"蓝色循环"，2023 联合国地球卫士奖） | 把它**下沉到"一次派单决策"这一粒度**：决策证据链带资产版本、本体版本、策略版本 |
| **可审计**智能任务流 + 使用审计（深圳"深 i 测"多智能体协同平台） | 加**人类审批闸门**：高风险动作必须挂起等待审批人，越权动作被策略守卫直接拒绝；且**重启后只读回放** |
| 海洋环境大模型 + 智能派单（青岛"智巡海湾"；青岛国实"灵龙"） | 不做通用大模型，做**受约束的决策运行时**：模型不可用时规则兜底照常工作 |

**答辩标准动作（必须主动说）**：先承认上述前序工作，再收口到**四元交集**——
① 智能体架构（规划/工具/记忆/反馈闭环）
② 显式决策证据链（处置建议可回溯到原始感知证据）
③ **人工审批闸门**（不自主执行治理动作）
④ 养殖区海漂垃圾场景 + 养殖主体可追责

> 检索未见 ≠ 不存在；绝对化断言（"首个"）的举证责任永远在提出方。**拿不出检索记录就不要写"首个"。**

## 1. 为什么要把主角从"系统"换成"治理智能体"

这不是换词，是**换主语**。

| 维度 | 旧叙事（系统） | 新叙事（治理智能体） |
| --- | --- | --- |
| 主语 | 我们造了一套区域级治理系统 | **它**会规划、会调工具、会被拦住、会留痕 |
| 价值落点 | 感知—决策—执行闭环 | 决策**可解释、可审批、可回放、可追责** |
| 评委记忆点 | 功能很多、页面很全 | 一个"敢让它自己跑，也说得清它做了什么"的智能体 |
| 面对"AI 在哪" | 容易退化成"我们用了 OpenCV" | 决策智能才是 AI；识别只是它的眼睛 |
| 面对"准不准" | 精度短板直接暴露 | 精度是**通道指标**，不是**智能体指标**（见 §5） |
| 赛道接口 | 一个技术系统 | 应用场景创新方向的"决策智能化" |

**一句话话术**：

> 别人做的是"识别垃圾的软件"，我们做的是"**敢让它在没有人盯着的时候替政府做一次派单决定、并且事后能复盘这次决定**"的治理智能体。

## 2. 三大亮点的外部依据（2025–2026 实证，2026-10-08 核查）

> 三条都**真存在、是当期热点**，但证据强度不同：**护栏与人工审批已是产品级能力**；
> **"审计回放"与"企业级证据链"目前只到框架级/学术级 —— 这正是本项目要填的工程缺口，
> 不是我们已经领先的地方。** 讲的时候必须区分这两类，否则一问就穿。

### 依据一 · 多智能体协同 + 护栏 + 人工审批 + 审计回放

**判定：真实现行（编排 / 护栏 / HITL 已是产品能力；"审计回放"只到框架级）。**

- **厂商已把它做成产品能力**：OpenAI AgentKit（2025-10-06 发布，含 Agent Builder / Guardrails / Evals；
  2026-06-03 公告于 11-30 下线，官方转向代码化的 Agents SDK）；Microsoft 于 2025-10 退役 AutoGen 并推出
  统一治理的 Agent Framework；LangChain / LangSmith 把 **human-in-the-loop 中断审批**与 **time travel 回放**
  做成产品能力。
- **需求侧数据（最有说服力的一段）**：Gartner 2025-06-25 预测「到 2027 年底 **超过 40% 的 agentic AI 项目将被取消**」；
  Gartner 2025-09-30 调研（2025 年 5–6 月，n=360 IT 应用负责人）显示**仅 15% 在考虑/试点/部署完全自主代理**，
  75% 处于某种试验或部署中，而**仅 13% 强烈认同治理到位**、**19% 高度信任厂商的防幻觉能力**。
  → **这正是"人工在环 + 审计留痕"是刚需而不是噱头的直接证据。**
- **监管在加压**：EU AI Act 第 50 条透明度义务自 **2026-08-02** 适用（罚则上限 1500 万欧元或全球营业额 3%）；
  中国《人工智能生成合成内容标识办法》2025-09-01 施行，**第九条要求留存日志不少于六个月**，
  第十二条要求算法备案/安全评估时提交标识材料（配套强制性国标 GB 45438-2025 同日实施）。
- **★ 中国 2026 年 7 月发布《人工智能 智能体互联》系列 7 项国家标准**（总体架构、**身份码**、身份管理、
  智能体描述/发现/交互/工具调用），据报道已累计发放 **2000 余个智能体"数字身份证"**，
  并明确「适时推进身份码标准向**强制性国标**转化、**加快智能体审计标准研制**」。
  → **这是"可审计治理智能体"叙事最强、最被低估的国家级依据，同时直接服务赛道"国产自主可控 20 分"。**

  [LangSmith HITL](https://docs.langchain.com/langsmith/add-human-in-the-loop) ·

  [Gartner 治理调研（日文官方页，含 15%/13%/19%）](https://www.gartner.co.jp/ja/newsroom/press-releases/pr-20251002-ai-ea-survey) ·

> ★ **诚实边界（必须讲）**：本项目的"审计回放"目前是**框架级/项目级**能力（进程重启后只读回放），
> **不是**行业标准，也**没有**通过任何审计认证。正确说法是

### 依据二 · 开放词汇零样本检测

**判定：真实现行（基准扎实，已在 Ultralytics 产品化；"工业免重训加类"仍属论文级）。**

- **CVPR 2024 的 YOLO-World**：LVIS 零样本 **35.4 AP**，V100 上 **52.0 FPS**（实时开放词汇检测的开端）。
- **ICCV 2025 的 YOLOE**（清华）：统一文本提示 / 视觉提示 / 无提示三种范式；
  LVIS 零样本 **YOLOE-v8-L 35.9 AP**、**v8-S 27.9 AP**（比 YOLO-Worldv2-S 高 **+3.5 AP**），
  训练成本约 **1/3**（12.0h / 8×RTX4090），T4 推理快 1.4×；稀有类增益 **+5.2 ~ +7.6 APr**。
- **产品化证据**：Ultralytics 已把 YOLOE 纳入主线文档，推理时可用文本提示或**内置 4,585 个名称词表**直接指定类别
  —— 这就是「新增类别无需重训」的技术支点，与本项目现场加词演示同源。
- 来源：[YOLO-World CVPR 2024](https://openaccess.thecvf.com/content/CVPR2024/html/Cheng_YOLO-World_Real-Time_Open-Vocabulary_Object_Detection_CVPR_2024_paper.html) ·
  [YOLOE 全文与数据表](https://ar5iv.labs.arxiv.org/html/2503.07465) ·
  [ICCV 2025 poster](https://iccv.thecvf.com/virtual/2025/poster/0205) ·
  [Ultralytics YOLOE 文档](https://docs.ultralytics.com/models/yoloe)

> ★ **诚实边界（必须讲）**：上述 35.4 / 35.9 AP 是 **LVIS 基准**上的零样本成绩；
> 本项目的公开基准（河流漂浮垃圾、4K 图像、小目标、强域外）上，**零样本通道的真实 mAP@0.5 明显低于此**
> （见 `docs/competitions/public-floatwaste-benchmark.md`）。**不得把 YOLO-World 的 LVIS 成绩说成本项目的成绩。**
> 也不得声称已实现"工业级免重训加类量产"，那目前仍是论文级证据。

### 依据三 · MCP 标准 + 知识图谱多跳检索与证据链

**判定：MCP 部分真实现行；「知识图谱 + 多跳检索 + 决策证据链」部分为**部分成立**。**
**MCP 部分**
- Anthropic 2024-11-25 开源发布；MCP 官方在 2025-11-25 规范发布博客中直接自称

  （新增 Task 工作流含 `input_required` 等状态、简化授权、官方扩展机制），注册表条目近 2000 条（较首批 +407%）。
- 2025-12-09 Anthropic 将 MCP 捐赠给 Linux Foundation 下的 **Agentic AI Foundation（AAIF）**
  （Anthropic / Block / OpenAI 共同发起，Google、Microsoft、AWS、Cloudflare、Bloomberg 支持），
  官方公布 **10,000+ 活跃公共 MCP 服务器**、Python + TypeScript SDK **月下载 9,700 万+**；
  ChatGPT、Gemini、Microsoft Copilot、VS Code、Cursor 均已接入。

**证据链部分**
- IJCAI 2025 的 **GE-Chat** 用知识图谱增强 RAG，结合思维链、**n 跳子图检索**与蕴含式句子生成，
  产出**带证据的回答**，目标即"验证 LLM 结论、提升可信度"；图 RAG 的系统性综述亦支撑
  「多跳检索 + 证据可追溯」是 2025–2026 企业知识助手主线。

> ★ **诚实边界（必须讲）**：
> (1) 企业级 MCP 落地仍早（单一来源调查：41% 称已进生产，但其中 86% 仍属实验/本地开发，**仅 5% 为受治理的企业级生产**）
> —— 该调查为二手单一来源，**不作为论据使用**；
> (2) 本项目的 R-KN-04 是 `hop_count=0` 的**直接引用检索**，**不是**真多跳，与 GE-Chat 的 n 跳子图不是一回事；

### 三条依据如何被我们使用（一句话）

> **护栏与人工审批**：已有产品级先例 → 我们做的是**把它落到县域海漂垃圾治理的具体动作上**；
> **开放词汇**：已有实时可用模型 → 我们做的是**把它接进"现场加词就能用"的治理闭环**；
> **MCP 与证据链**：MCP 已是事实标准、证据链尚是缺口 → 我们**用标准协议把缺口补上**。
> 三段话的落点都是**工程落地**，而不是"我们比大厂强"。

## 3. 三大亮点（都真实存在、都有代码位置、都能现场演示）

### 亮点一 · 多智能体协同：规划 → 工具调用 → 策略守卫 → 人工审批 → 审计回放

**命题**：这个智能体不是"一问一答"，而是跑在一条**有闸门、有留痕**的状态机上。

**落到代码（可当场打开指认）**：

| 环节 | 实现 | 位置 |
| --- | --- | --- |
| 状态机 | `created → planning → waiting_policy → waiting_approval → executing → observing → verifying → succeeded / failed / cancelled / expired`（终态不可再迁移） | `backend/app/services/agents/runtime.py` |
| 规划 | `RulePlanner` 规则计划 + 可选 OpenAI-compatible 模型规划（`ModelAdapterPlanner`），模型不可用时**规则兜底照常工作** | `planner.py`、`model_adapter.py` |
| 工具调用 | `ToolRegistry` / `ToolExecutor`，每次调用写 `input_hash` / `output_hash` | `tools.py` |
| **策略守卫** | `PolicyGuard` 协议 + `RulePolicyGuard` 确定性实现：`check_tool` 校验角色是否在工具 `allowed_roles` 内；`risk_level` 达阈值 → `requires_approval=True`；`check_plan` 做**计划级聚合预检**，判定带 `policy_version` | `policy.py` |
| **人工审批** | 命中审批的动作**一次性创建审批单并挂起**（`waiting_approval`），`ApprovalRepository.decide` 记录审批人；超时按 `approval_timeout_ms` 判 `APPROVAL_TIMEOUT`；拒绝判 `APPROVAL_REJECTED` | `runtime.py::_stage_policy` / `_resolve_approvals`、`repositories.py` |
| 观察→验证→重规划 | `_check_expectation` 返回 `ok / terminate / replan`；失败追加 `verification(failed)` + `replan` + 新 `plan` 步骤，**追加不覆盖** | `runtime.py::_replan` |
| **审计回放** | 轨迹**只写决策摘要**与 `input_hash`/`output_hash`，**不保存模型思维链**（解密预算）；`_result(idempotent_replay=True)` 支持幂等重放；`persistent_repository` 支持**进程重启后对已完成 run 只读回放** | `runtime.py`、`persistent_repository.py` |
| 经验沉淀 | run 到终态做一次确定性复盘，可复用结论沉淀为经验；规划阶段检索跨 run 经验 | `lessons.py`、`runtime.py::_harvest_lessons` / `_consult_lessons` |

**已实证（E1/E2）**：23/23 Agent 固定场景评测通过；Agent E2 真实状态集成验收 **129/129**（真实 HTTP、角色权限、PostgreSQL 仓储、WRITE 审批、幂等、**进程重启后已完成 run 只读回放**）。

**60 秒现场演示脚本**：
1. 以**只读角色**发起一次派单 → 策略守卫直接拒绝，界面显示拒绝理由与 `policy_version`；
2. 换**值班员角色**发起同一动作 → 放行但挂起在 `waiting_approval`；
3. 用**审批人账号**批准 → 执行 → 观察 → 验证通过；
4. 打开该 run 的轨迹：每一步的决策摘要、工具、哈希、审批人、时间戳；
5. **重启后端**，重新打开同一 run → 轨迹只读回放，一字不差。

**诚实边界（必须主动说）**：当前是**进程内确定性运行时**，不是生产级、高可用、分布式；重启后只能对**已完成**的 run 只读回放，**未完成的 run 不能在重启后续跑**；可选模型规划客户端已完成接线但默认关闭。

### 亮点二 · 开放词汇零样本检测：评委说一种垃圾，系统当场学会识别

**命题**：传统检测器"加一个类别 = 重采、重标、重训"；开放词汇通道"**加一个类别 = 改一个词**"。

**落到代码**：

| 能力 | 实现 | 位置 |
| --- | --- | --- |
| 开放词汇检测 | `WorldDetector`（YOLO-World），`set_prompts()` 运行时直接换词表 | `edge/detector/world_detector.py` |

**现场演示脚本（最有记忆点的一段）**：
> 让评委随口说一个词 —— "泡沫浮球""塑料瓶""渔网""木板"；
> 现场把它敲进命令行 → **不重训、不重标、不重启服务**，下一帧直接出框。
> 对照：同样这件事走自训练 YOLO 路线要 3~4 周（采集 → 标注 → 训练 → 导出 → 部署）。

**已实证的、必须主动交代的边界**（这些都是踩过的真坑，讲出来是加分不是减分）：

- **置信度尺度不同**：`0.45` 是给 OpenCV 通道伪置信度标定的时序门限；开放词汇通道分数低一个量级，历史实测 5 张 4K 演示原图**最高只有 0.413，且没有一条 ≥0.45**。若共用 0.45，该通道检测会在时序环节被**全部丢掉且不报错**。故本通道有独立门限 `detector.world.temporal_min_confidence`（默认 **0.02**）。
- **0.02 是"四类皆可报"的演示工作点，不是精度最优值**，不得写成"最优"或"经标定"。
- **合成帧不适用于本通道**：程序化绘制的纯色圆盘缺少外观纹理，原始输出即为 0。这 0 条**不得读作"通道无效"**。
- **权重路径按仓库根解析**，不按 cwd；默认禁止联网下载，找不到权重直接报错而不是静默下载。

**精度**：见 §5 —— 已用公开漂浮垃圾基准独立测试集给出**真实数字**，不再是 `not_evaluated`。

## 4. 三个亮点如何咬合成**一个**智能体（不是三条并列功能）

评委最容易给的差评是"这不就是三个功能堆在一起吗"。正确的讲法是**一条链**：

```
   ①看                ③想                      ①管                     ①记
开放词汇零样本  →  多跳检索 + 决策证据链  →  策略守卫 + 人工审批  →  审计回放
"现场能加词"       "结论有出处"              "越权被拦住"           "事后能复盘"
```

| 环节 | 如果不这样做，会怎样 |
| --- | --- |
| 开放词汇（看） | 每来一类新垃圾就要重训，现场第一次遇到新垃圾就瞎 |
| 多跳检索 + 证据链（想） | 智能体会编理由；政府不敢把决定权交给一个说不清依据的东西 |
| 策略守卫 + 审批（管） | 一个幻觉就能触发一次真实派单，责任无人承担 |
| 审计回放（记） | 出了事无法追责，也就无法通过政务/等保与算法备案口径 |

**一句话总结这条链**：
> 我们不是让 AI 更准，而是让 AI **可以被放进真实治理流程里** —— 它看得见新东西、说得清理由、被管得住、事后查得到。

## 5. 精度口径（本节数字由评测脚本产出，不得手写）

**核心转折**：感知精度不再写 `not_evaluated`。

- 独立测试集：**SC-FloatWaste 公开漂浮垃圾基准**（HuggingFace `OliviaWuYJ/sc-floatwaste`，
  Zenodo DOI `10.5281/zenodo.21934286`，**CC BY 4.0**）**官方 `val` 划分**的 400 张确定性子集，
  覆盖 Indonesia（Citarum 流域）/ Australia NSW / Tasmania Hobart 三个区域。
- 训练集/验证集取自**官方 `train` 划分**（Indonesia 600 / 172）。官方声明两划分不相交，
  故"训练没见过测试图"由数据集发布方保证，不依赖本仓库随机切分。
- 产出物：`artifacts/metrics/public_floatwaste_*.json` + 清单 `ml/datasets/manifests_public/`。
- 详细方法与全部数字：`docs/competitions/public-floatwaste-benchmark.md`。

### 5.1 主结果（独立测试集 400 张 / 1,490 框 / 三区域）

| 通道 | mAP@0.5 | mAP@0.5:0.95 | best-F1 |
| --- | ---: | ---: | ---: |
| 开放词汇零样本（出货词表，imgsz=960） | 0.1432 | 0.0930 | 0.2702 |
| **YOLO11s 微调**（印尼 600 张训练 60 轮，imgsz=1280） | **0.5135** | **0.3444** | **0.5376** |

**分区域** —— 训练集只来自 Indonesia，故 NSW/Hobart 是完全跨域：

| 区域 | 每图框数 | 零样本 mAP@0.5 | YOLO11 微调 mAP@0.5 | 训练域 |
| --- | ---: | ---: | ---: | --- |
| Indonesia | 9.44 | 0.1299 | **0.7229** | ✅ |
| NSW | 1.24 | 0.2105 | **0.3341** | ❌ 跨域 |
| Hobart | 2.99 | 0.2408 | **0.4029** | ❌ 跨域 |

**三句话话术**（答辩直接用）：
1. **数字**：在第三方公开漂浮垃圾基准的 400 张独立测试集上，有监督微调通道
   **mAP@0.5 = 0.5135**，零样本通道 0.1432；两条通道差 3.6 倍 ——
   开放词汇通道的价值在**"现场加词就能用"**，精度靠可训练通道，二者分工有量化依据。
2. **训练域 0.7229**： Indonesia 每图 9.44 个框、目标又小又密，这是**连江养殖区泡沫碎片的真实形态**，
   0.72 说明这个形态是可解的。
3. **跨域 0.33–0.40，而且"延长训练会让跨域变差"**：第 14 轮时跨域 NSW 是 0.4431、训满 60 轮后降到 0.3341，
   同期训练域从 0.6271 升到 0.7229。**结论：域适配要靠多区域数据，不是靠多训** ——
   这正是"必须自己采连江数据"的量化论据。

★ **主动披露**：训练第一轮到第 15 轮时因宿主内存不足（4K 图像 × 4 worker）中断，
降 worker 后 `resume` 续训跑满 60 轮。如实说，是工程可信度的一部分。

**★★ 口径红线（写死，不得违反）**：

1. 这批影像是**第三方公开数据**（印尼 / 澳大利亚），**不是连江海域、不是本项目设备**。
   只能写「**在公开漂浮垃圾基准独立测试集上的精度**」；
   **禁止**写成「连江现场验证」「真实海域验证」「本项目设备实测精度」。
2. 清单 `evidence_level: E3` 指的是**底层影像为真实场景数据**，
   **不是**「本项目已完成现场验证」。
3. `76%` 仍然**只能**表述为「时序链路误报抑制率」，与本节精度无关，禁止混用。
4. 单类 `litter` 的 mAP 与四契约类（foam/plastic/fishing_gear/other）的分组指标必须分开写；
   四类分组是**本项目自行定义的近似映射**，不是数据集官方标注。
5. 交付答辩前必须能现场复跑评测脚本；不能复跑的数字不得写进材料。
