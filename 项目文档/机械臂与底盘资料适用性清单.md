## 二、总线舵机 SDK（已接入）

资料路径：

```text
6.总线舵机二次开发教程-树莓派版本\程序文件\
  案例1~5\ros_robot_controller_sdk.py
```

已确认接口：

- `Board(device="/dev/ttyAMA0", baudrate=1000000, timeout=5)`
- `bus_servo_set_position(duration, [[servo_id, position], ...])`
- `bus_servo_stop([servo_id, ...])`
- `bus_servo_enable_torque(servo_id, True/False)`
- `bus_servo_read_id / read_position / read_vin / read_temp`
- `enable_reception(True)` 后 `get_battery()` 返回裸 mV

桥接层已按这套接口实现 `HiwonderBusServoArmDriver`，注册名
`hiwonder_bus_servo`。到货后把 SDK 放到树莓派桥接层同目录、装
`pyserial` 即可；缺 SDK 时物理动作会明确报 `DriverError`，不会假装成功。

## 三、示教记录与回放（已接入）

商家「案例5 示教记录实现」是当前最稳的真机接入方式：手动掰机械臂到
目标姿态 → `bus_servo_read_position` 记录位置 → 回放。这个思路已经映射到
驱动配置的 `pick_sequence`。

仓库新增工具 `edge/arm_bridge/tools/teach_hiwonder_sequence.py`，支持多舵机
逐姿态录入，输出 JSON 后由驱动通过 `pick_sequence_file` 直接读取：

```bash
python edge\arm_bridge\tools\teach_hiwonder_sequence.py \
  --servo-ids 1 2 3 4 5 6 --duration 1.0 --output pick_sequence.json
```

注意：示教位置是 0..1000 的舵机位置，不是经纬度，也不是相机坐标系下的
末端坐标。

## 五、色块识别与追踪（演示辅助）

第5~7课的核心链路：Lab 颜色空间二值化 → 最大轮廓 → 中心点/面积 →
PID 从二维图像推三维偏移 → 逆解 → 舵机脉宽。这个链路只能作为受控实验
演示的参考实现，不改动感知精度口径：

- 感知精度保持 `not_evaluated`；
- 「链路跑通」不等于「识别准了」；
- 真机械臂 + 仿真海面 / 受控实验标 **E2**。

## 六、机械爪位置自适应（指导示教编排）

第8课给出可复用的动作编排：

- 1 号舵机：机械爪张 / 闭；
- 2 号舵机：`500 + int(F * 目标旋转角)`，让机械爪与目标平行；
- 3/4/5 号舵机：靠近、抬升、回中位；
- 6 号舵机：末端水平偏移（追踪时来自 `x_dis`）。

真机联调时按这个顺序设计 `pick_sequence`：对齐 → 靠近 → 夹取 → 抬升 →
回位。是否需要 2 号平行修正，以实物机械臂结构和目标摆放为准。

## 八、麦轮底盘（接口已确认，暂未接桥）

`ros_robot_controller_sdk.Board` 支持：

```python
board.set_motor_speed([[motor_index_minus_one, speed], ...])  # 1~4 号麦轮
board.set_motor_duty([[motor_index_minus_one, duty], ...])
board.get_battery()  # 裸 mV，SDK 无电量百分比
```

如果机械臂装在麦轮底盘上，需要「平台指令驱动底盘移动」时，按现有
`ArmDriver` 的模式新增一个底盘 `Driver` 和对应动作即可；桥接层结构不变。
蓝牙 APP、PS2 手柄、STM32 出厂程序只适合开发期调试，不走平台 MQTT 链路。
