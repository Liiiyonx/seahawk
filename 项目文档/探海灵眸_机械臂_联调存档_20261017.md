## 六、当前阻塞：视觉模型在室内场景失效

### 6.1 实测证据

同一观测姿态连取 12 帧，按中心聚类投票：

| 簇 | 命中 | 指向 |
| --- | --- | --- |
| #1 | **12/12** | 🔴 **机械臂自己的夹爪** |
| #2 | 10/12 | 右上角地面/墙角白边 |
| #4 | **2/12** | ✓ 真袋子 |

同一姿态连取 5 帧、`conf≥0.50` 的检出数：**`[1, 0, 2, 0, 0]`**（逐帧不稳）。

袋子在画面占约 **250×290 像素**，模型给它的框只有 **20×22 像素**。

### 6.2 补充验证

把臂沿 x 移动 3cm，检测框像素几乎不动（`Δ=(-0, +7)`）——
**静止世界物体不可能这样**，证明锁的是随臂运动的夹爪。

### 6.3 经典图像处理也失败（都试过）

| 方法 | 结果 |
| --- | --- |
| Canny 边缘 + 轮廓 | 3 张图里 2 张 0 候选（对比度低，边缘碎） |
| 高斯自适应阈值 | 选出整块地面 |
| 局部方差（纹理） | 框出 565×408 ≈ 整屏 |
| 亮度亮块 + ROI + 尺寸过滤 | 选出地面亮斑，不随高度变化 |

**根因**：白袋子放在浅色地面上，亮度/饱和度/纹理都与地面接近，
在这个光照下**可分离度不足**。这是场景的物理限制。

### 6.4 两条可行出路

**① 垫深色背景（5 分钟，最快）**
白袋子放在深色布/黑纸板上 → 对比度几十倍 → 轮廓检测变成教科书难度。
之后可做「识别轮廓 → 取中心 → 慢速抓放」。

**② 现场特化模型（20~30 分钟）**
作业台 `1 采集 → 2 标注 → 3 一键场景校准 → 4 部署`。
拍 60~100 帧、框出袋子。不需要换背景，但费人工。

## 七、已知缺陷（下次动手前先看）

| # | 缺陷 | 影响 | 修法 |
| --- | --- | --- | --- |
| 1 | **标定是单点平移近似** | 视觉伺服会朝错误方向驱动，曾导致爪子压到贴住表面 | 用 `calib_point.py` 采 4 个真实点重做仿射拟合 |

## 八、踩过的坑（按严重程度）

### 8.1 `ExecStartPost` 把服务弄挂（最严重）

曾用 `ExecStartPost=board_apply_boot_pose.py` 做开机摆位，结果服务**反复失败、8093 完全不监听**：

```
Start-post operation timed out. Stopping.
Failed with result 'timeout'
```

**原因**：systemd 里 `ExecStartPost` 与 `ExecStart` 是**同时**开始的，不是"之后"。
主进程要 ~80s 才把 board_agent 拉起来，而 Start-post 超时远小于它。

**修法**：改用**独立 oneshot 单元** + `After=`/`PartOf=`。
（两个单元文件里都写了注释，别改回去。）

### 8.2 三个 `roslaunch` 并行启动互抢 rosmaster

```
RLException: run_id on parameter server does not match declared run_id
```

**修法**：先单独起 `roscore` 等它应答，再**顺序**起三个 launch。

### 8.3 CRLF 导致 `roslaunch` 报"不是 launch 文件名"

Windows `scp.exe` 把 LF 转成 CRLF → bash 数组元素带 `\r` →
`roslaunch "${ARR[1]}"` 失败，而**手打字面量却正常**。
**修法**：脚本内置 CRLF 自愈；`.gitattributes` 声明 `*.sh text eol=lf`。

### 8.4 前端 `api()` 的 GET/POST 陷阱

`api(url)` 原本「不传 body 就发 GET」，而一批无参动作端点（`/api/home`、
`/api/gripper`、`/api/calibrate/save`、`/api/evaluate`）**全是 POST-only** →
按钮点了**静默没反应**（只在控制台一行 405）。

**修法**：`api(url)` 默认 POST；只读查询显式写 `api(url, 'GET')`。
已加回归测试（含**突变验证**：把默认改回 GET，测试会红）。

### 8.5 我犯的两个错（值得记）

- **用 `from __future__ import annotations` 写板上脚本** —— 板上 py3.6 直接
  `SyntaxError`。同一 session 里刚记录过这个坑，却又踩了一次。
- **拿「1 个检出点 + 估算尺度」当标定** —— 为了赶进度走了捷径，
  直接导致闭环朝错误方向下压、爪子贴住表面。正确做法是 4 点拟合。

- `--mock` / 合成画面 / 留出集指标**都不能当作验收证据**
- 感知精度只以留出集 mAP 表述，并注明**非现场精度**
- `ok`（夹到了）与 `placed`（真的放进槽了）**必须分开报**
- 真机 + 受控实验只能标 **E2**，不得写成 E3/E4
- 「链路跑通」≠「识别准了」
