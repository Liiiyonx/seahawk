# 探海灵眸 Oceanus —— 评委与产品经理双视角分析

> 基于《探海灵眸_项目计划书.md》《Harness_分工执行手册.md》与仓库当前实现状态（2026-09-22：1061 项测试全部通过、23/23 Agent E1 固定评测、Agent E2 真实状态集成验收 129/129、OpenCV 传统视觉检测器、FastAPI+Vue3 平台、契约脚本与自证体系）。
> 本文只做能力评估与差距分析，不构成获奖承诺。按项目自身 E0-E4 纪律：E0 规划假设 / E1 内部实现证据 / E2 受控实验 / E3 真实场景 / E4 规模化验证。

## 一、评委老师视角（创新创业类比赛评审）

### 1.1 总体判断

- **选题与价值主张：国奖级选题。** 海洋垃圾治理同时命中「海洋强国」「双碳/生态治理」「数字乡村/智慧渔业」多类政策热点；连江本地公开背景涉及 2023 年 1—10 月清理 2.92 万吨、746.72 万粒浮球改造等（F-01/F-02，均待核原文），场景具体、可调研、可量化——这是评委容易共情、也值得继续验证的起点。
- **工程纪律与可信度：当前最硬的差异化。** 1061 项测试全部通过、0 跳过、0 failed、23/23 Agent E1 固定评测、Agent E2 真实 HTTP/PostgreSQL/审批/幂等/重启只读回放 129/129、契约漂移自证、E0-E4 证据纪律、拒绝 stub 造假——在本届团队项目中，这是很突出的工程可信度，答辩时可以用测试原始输出和数字台账支撑每项主张。
- **明确短板：** ① 无 E3 级证据（真实海域/真实用户访谈/真实询价/试点数据）；② 无硬件原型（机器人是路线图不是实物）；③ 识别算法是 OpenCV 传统视觉，独立测试集为空，当前只能写 `not_evaluated`；④ 商业证据台账和访谈/询价模板已建立，但尚未取得外部回执。**当前达到国奖候选工程基线，离获奖仍取决于团队能否把真实证据补齐。**

| 社会价值与政策契合 | 三重命中赛道方向，连江「世界渔都」IP 绑定 | 高 | 保持；把「治理效果可量化」做成向政府汇报的抓手 |

### 1.3 国奖差距清单（按优先级）

1. **E3 证据缺口（最大短板）**：至少 1 个真实试点/真实调研/真实访谈记录；1 份真实供应商询价回执。→ WP-08 模板落地 + 团队执行。
2. **硬件可信度**：机器人原型或与本地清漂船/回收点合作的实物证据。→ 路线图已诚实分期，答辩口径「岸基先行」。
3. **AI 叙事**：OpenCV 不得写成 YOLO；智能体（Agent Runtime）是当前技术热点，把「有人审批的自动化派单 Agent」讲成创新点，比「AI 识别」更站得住。
4. **商业闭环证据**：试点合同意向函/政府对接记录（E3 起点），而非纯测算。
5. **知识产权**：软著（平台+Agent 内核）、实用新型（分拣仓/收集机构）。

### 1.4 评委必问 10 题（答辩演练清单）

1. 「你的 AI 创新在哪？」→ 答：工程在闭环系统与 Agent 决策，识别走零数据依赖的 OpenCV 冷启动，YOLO 接口预留，诚实且可现场调参。
2. 「准确率多少？」→ 答：独立测试集为空，当前没有可报告精度；42%~76% 只是不同合成输入集上的时序误报抑制率（被过滤检测数 / 输入检测数，口径见 README 与 architecture.md），待真实海域和独立样本完成 E3 验证后再报告 precision/recall。
3. 「谁付费？为什么现在付？」→ 答：政府购买服务对标现有清运经费与「每粒 1 元」补贴；政策考核驱动。
4. 「一个机器人多少钱？」→ 答：测算价/目标价/成交价分开讲（WP-08 台账）。
5. 「硬件抗风浪吗？」→ 答：阶段策略——岸基先行、静水验证、成熟船体方案。
6. 「为什么不用 WasteShark？」→ 答：进口单价高、不识别养殖区垃圾、无区域级平台、无闭环。
7. 「数据和竞品差异？」→ 答：热力图/溯源/派单/量化报表 = 治理工具，不是单机清洁船。
8. 「智能体是噱头吗？」→ 答：现场演示离线轨迹：发现→策略→审批→派单→执行→验证→归档。
9. 「团队凭什么做硬件？」→ 答：硬件分阶段，软件平台已通过 1061 项全量测试且 0 failed、23/23 Agent E1 固定评测和 Agent E2 真实状态集成验收；硬件团队、指导老师和本地产业资源用于后续原型与供应链验证。
10. 「怎么规模化？」→ 答：连江→福州沿海→全省养殖区；模式从政府购买服务复制。

## 二、产品经理视角

### 2.1 一句话产品定义

> 面向县域海漂垃圾治理的「感知—决策—执行」闭环系统：卖的不是一台清洁船，而是一套**可量化、可考核、可复制的治理结果**。

### 2.2 干系人模型（决策链比用户更关键）

| 角色 | 是谁 | 痛点 | 付费/预算机制 | 成功标准 |
|---|---|---|---|---|
| 用户 | 乡镇海渔站/环卫队 | 打捞效率低、盲区大 | 专项经费（清运、回收点运维） | 清理量上升、投诉下降 |
| 购买者 | 县海渔局/生态环境局 | 治理效果无法量化考核 | 财政购买服务/专项 | 报表能向上级汇报 |
| 预算方 | 县政府/财政局 | 预算有限、要政绩可见 | 年度预算、专项行动资金 | 投入产出可解释 |
| 操作员 | 环卫工人/平台值班员 | 临水作业危险、手工记录繁琐 | —（被替代的高风险环节） | 系统易用、减少危险作业 |
| 验收方 | 上级部门/考核组 | 缺量化数据 | — | 治理前后对比数据可信 |

**PM 结论：产品必须同时讨好「购买者要的报表」与「操作员要的易用」，缺一不可。** 首单打法是「先送报表能力，再谈设备」。

### 2.3 价值主张与付费锚点

- 核心卖点：把「人海战术清理」变成「可量化治理资产」——热力图、派单工单、治理前后对比，直接对接政府考核语言。
- 付费锚点三件套：马鼻镇「每粒 1 元」收捡补贴、海漂垃圾清运专项经费、人工打捞的人力+安全成本。**第一版商业材料必须把这三项成本算清楚（单位经济性），否则定价无依据。**
- 碳汇/蓝色碳票是长期想象空间（连江全国首例制度基础），但不得写进近期收入。

### 2.4 产品形态与落地路线（先软件后硬件）

1. **MVP（当前）**：岸基摄像头 + 边缘 OpenCV + 平台派单 + 报表。零硬件自研风险，纯软件闭环。
2. **第一阶段试点**：在 1 个乡镇（马鼻/黄岐）部署 2-3 个点位 + 平台，用真实垃圾事件验证「发现→派单→人工或机器人打捞→回传」闭环，产出第一份 E3 数据。
3. **第二阶段**：水面机器人原型（静水→近岸→航道上）。
4. **第三阶段**：系统复制（福州沿海→全省）。

**关键 PM 判断：不要等机器人成熟再卖系统。** 先卖「监测+调度+考核」服务，机器人是增购项。

### 2.5 核心指标体系（产品必须定义并长期跟踪）

| 指标 | 定义 | 现状 |
|---|---|---|
| 清理量（吨/月/点位） | 工单回传真实量 | 数据真实但不含硬证据（WP-08 台账） |
| 单吨清理成本 | 含人工/设备/平台摊销 | 未测算（WP-08 补） |
| 发现→派单→完成时长 | 端到端 SLA | 引擎已实现，待试点实测 |
| 时序误报抑制率 | 被时序过滤的检测数 / 输入检测数；合成链路 42%~76% | 已复现两种输入集口径，不是识别精度或召回率 |
| 覆盖率 | 监测点位覆盖 vs 盲区 | 无可靠来源时 `coverage_area=NULL`，导出留空，不写假 0 |

### 2.6 商业模式验证路径（第一个订单从哪来）

1. **动作一**：用 WP-08 的访谈模板完成 5-10 份真实访谈（乡镇海渔站/海渔局/环卫队），拿到付费意愿与验收标准的一手证据（E3 起点）。
2. **动作二**：用询价模板拿到真实 BOM 报价，验证「国产化成本优势」是否成立——若成本压不下来，国产化叙事失效，必须重新定价。
3. **动作三**：争取 1 份试点意向（政府对接记录/意向函），哪怕是无偿试点——「连江首个智慧海漂治理试点」本身就是商业里程碑。
4. **动作四**：试点出数后，用「治理前后对比报表」做复制谈判。

### 2.7 风险清单（PM 视角）

| 风险 | 等级 | 缓解 |
|---|---|---|
| 硬件自研失败 | 高 | 先软件后硬件；成熟船体方案；打捞机构外协 |
| 政府预算不足 | 中 | 对标现有经费；先试点后收费；SaaS 化监测订阅 |
| 识别不准被质疑 | 中 | 诚实口径+时序抑制+现场调参演示 |
| 数据合规 | 中 | 政务云部署；天地图；等保意识 |
| 团队学生身份 | 中 | 指导老师+注册实体+本地产业资源 |
| 商业数字无来源 | 高（当前） | WP-08 台账落地，答辩前全部可追溯 |

## 三、结论

- **评委视角**：选题、工程纪律、软件闭环、政策契合已达国奖候选工程基线，内部红队评分约 80/100；缺口集中在 E3 真实证据、硬件可信度与感知评测。当前最重要的三件事：取得真实访谈/询价/测试记录，完成独立感知评测，推进 1 个真实或准真实试点。
- **PM 视角**：产品定义清晰（卖治理结果而非设备），路线正确（先软件后硬件、先试点后收费）；最紧迫的是把「付费锚点成本账」算出来、把真实访谈与询价跑起来，让商业模式从「故事」变成「台账」。
- **下一步**：软件第一波与第二波已形成可复现证据包；WP-09 的 Agents 页面浏览器回归已完成 3/3，WP-18 的真实 HTTP/权限/PostgreSQL/审批/幂等/重启只读回放已完成 129/129，正式材料随本次计划书重建并逐页验收。之后应把工作重心从继续堆软件功能转向真实用户、供应商、现场和设备证据，目标是把 E1/E2 工程证据推进到 E3/E4。
