# 第6课 MoveIt 运动学设计

## 1. 运动学介绍

- 运动学 = 从**几何角度**出发（**不涉及物体本身的物理性质、不涉及加在物体上的力**）描述和研究物体位置随时间变化的规律，是力学的一个分支。
- **正运动学（Forward Kinematics, FK）**：给定关节变量的取值 → 确定末端执行器的位置和姿态。即"从舵机旋转的角度来确定机器人最终的位置和姿态"。
- **逆运动学（Inverse Kinematics, IK）**：给定末端执行器的位置和姿态 → 确定机器人关节变量的取值。即"从机器人最终的位置和姿态，反向推算舵机需要旋转的角度"。

> 补充（工程视角）：FK 唯一解、计算廉价，是实时控制内环；IK **多解**（肘部上/下、腕部翻转 4 组），可能无解（超出可达空间），是 MoveIt 规划器每一步都要调用、也是最容易失败的环节。

## 2. 正运动学简析

### 2.1 DH 参数介绍

DH（Denavit-Hartenberg）参数 = 用**四个参数**表达**两对关节—连杆之间位置/角度关系**的机械臂数学模型与坐标系确定系统。四个参数都有非常明确的物理含义：

1. **link length（连杆长度）**：两个关节的轴（旋转关节=旋转轴，平移关节=平移轴）之间的**公共法线长度**。
2. **link twist（连杆扭转）**：一个关节的轴相对于另一个关节的轴，**绕它们的公共法线**旋转的角度。
3. **link offset（连杆偏移）**：一个关节与下一个关节的公共法线，和它与上一个关节的公共法线，**沿这个关节轴**的距离。
4. **joint angle（关节转角）**：一个关节与下一个关节的公共法线，和它与上一个关节的公共法线，**绕这个关节轴**的转角。

课件原话："以上定义看了很绕口，但是结合坐标系看就会清楚许多。"

### 2.2 坐标系确定（含DH 约定的核心两条线）

**先记住最重要的两条"线"**：
- 一个关节的**轴（axis）**
- 一个关节的轴与**相邻关节的轴之间的公共法线（common normal）**

**DH 体系的两条铁律**：
- `axis` → 定为 **z 轴**
- `common normal` → 定为 **x 轴**，且 **x 轴方向为：从本关节指向下一个关节**

> 补充（URDF/MoveIt 与 DH 的差异，务必分清）：URDF 里每个 joint 的坐标系是**独立指定 `<origin xyz rpy>`** 的，不强制满足"z=axis、x=common normal"；DH 是严格串行链式约定，只适用于串联链。MoveIt/KDL 实际用的是 URDF 语义，所以第6课的 DH 法则**不能直接照搬到 URDF 里**——URDF 里你只需保证 `<axis>` 与 joint 原点 z 轴一致。

**确定坐标系的一般步骤**（课件原文顺序）：

**第1 步 — 为每个关节指定参考坐标系**。用 DH 表示法建模，第一件事就是为每个关节指定参考坐标系，因此**每个关节都必须指定一个 Z 轴和 X 轴**。

**第 2 步 — 指定 Z 轴**
- 关节是**旋转**关节：Z 轴位于**按右手规则旋转**的方向；绕 Z 轴的旋转角就是**该关节的变量**。
- 关节是**滑动（平移）**关节：Z 轴为**沿直线运动的方向**；沿 Z 轴的连杆长度 d 就是**该关节的变量**。

**第 3 步 — 指定 X 轴（公垂线规则）**
- 两关节**不平行也不相交**时：Z 轴通常是斜线，但总有一条**距离最短的公垂线**（common normal），它**正交于任意两条斜线**。在公垂线方向上定义本地参考坐标系的 X 轴。
- 若`a_n` 表示 `Z_n` 与 `Z_(n-1)`（课件原文写作 `Zn1`）之间的公垂线，则 `X_n` 的方向沿 `a_n`。

**第 4 步 — 特殊情况处理（可简化模型）**
- **两关节 Z 轴平行** → 存在**无数条**公垂线。此时**挑选与前一关节的公垂线共线**的一条，以简化模型。
- **两关节相交** → 它们之间**没有**公垂线。此时将**垂直于两条轴线构成的平面的直线**定义为 X 轴，以简化模型。

**给每个关节都附上对应坐标系之后**（课件图示为 6 关节平面臂，含基座 `X0/Y0/Z0`，各关节 `X1..X6`、`Y0..Y4`、`Z0..Z4`，标注 `l1 l2 l3 l4 l5` 与 `d1 d2`）：

**确定好坐标系后，用更简洁的方法重述四个参数**（课件 2.2 节末尾原文，与 2.1 节的文字定义等价）：

| 参数 | 课件简写 | 精确定义（课件原文） |
|---|---|---|
| link length（连杆长度） | `α_(i-1)` | 沿 `X_(i-1)`，从 `Z_(i-1)` 到 `Z_i` 的距离 |
| link twist（连杆扭转） | `α_(i-1)` | `Z_i` 相对于 `Z_(i-1)` 绕 `X_(i-1)` 旋转的角度 |
| link offset（连杆偏移） | `d_i` | 沿 `Z_i`，从 `X_(i-1)` 到 `X_i` 的距离 |
| joint angle（关节转角） | `θ_i` | `X_i` 相对于 `X_(i-1)` 绕 `Z_(i-1)`…（原文在此处笔误/截断） |

> ⚠️ **课件笔误（必须知道，否则会记错）**：连杆长度与连杆扭转两项，课件的符号**都写成了 `α_(i-1)`**。按 DH 标准记法应为：
> - 连杆长度 = `a_(i-1)`
> - 连杆扭转 = `α_(i-1)`
> - 连杆偏移 = `d_i`
> - 关节转角 = `θ_i`
>
> 第 3 节的逆运动学推导里也明确用了 `a`、`b`、`c` 作为二次方程系数，说明符号体系本来就混着走。**记住物理含义（沿哪个轴量哪两点的距离/角度）比记住字母可靠**。另外 `θ_i` 那行原文写"绕 `Z_(i-1)`"，标准 DH 应为绕 **`Z_i`**。

> 补充（DH → 齐次变换）：完整描述一节只需 `a, α, d, θ` 四个量，齐次变换矩阵为
> `T(i-1,i) = Rz(θ_i)·Tz(d_i)·Tx(a_i)·Rx(α_i)`，链式相乘 `T_0_n = Π T(i-1,i)`，末端位姿 = `T_0_n · [0,0,0,1]`。正运动学就是纯矩阵乘法，没有分支、没有多解。

## 3. 逆运动学简析（几何法 / 解析法）

**模型简化**：机械臂三维运动复杂，**去掉下方云台的旋转关节**，从而在**二维平面**上做运动学分析（去掉底座云台和执行器部分，得到机械臂主体）。

**为什么用几何法**：逆运动学一般要进行**大量矩阵运算，过程复杂、计算量大，所以实现起来较难**；为了更好地适应需要，**使用几何法**对机械臂进行分析。

**几何关系**（课件配图：平面三连杆 + 绿色直角坐标系分解 x1..x3 / y1..y3，端点 P）：
- 端点 P 的坐标 `(x, y)` 由三部分组成：`(x1+x2+x3, y1+y2+y3)`
- `θ1, θ2, θ3` 就是要求解的舵机角度；`α` 是爪子与水平面的夹角
- 爪子俯视角：`α = θ1 + θ2 + θ3`

**列方程（课件原式）**：

```
x = l1·cos(θ1) + l2·cos(θ1 + θ2) + l3·cos(θ1 + θ2 + θ3)
y = l1·sin(θ1) + l2·sin(θ1 + θ2) + l3·sin(θ1 + θ2 + θ3)
```

其中 `x, y` 由**使用者给出**，`l1, l2, l3` 为机械臂的**机械结构固有属性**（不可改）。

**化简第一步（整体考虑已知部分）**，令 `m = l3·cos(α) - x`、`n = l3·sin(α) - y`，代入已有方程再化简得：

```
l2² = (l1·cos(θ1) + m)² + (l1·sin(θ1) + n)²
```

**解一元二次方程**（展开上式即可得到关于 `sin θ1` 的一元二次方程）：

```
                 -b ± √(b² - 4ac)
sin(θ1)  =  ─────────────────────────
                      2a
```

其中：

```
a = m² + n²

        -n(l1² - l2² - m² - n²)
b = ─────────────────────────────
                  l2

        ⎛ l1² - l2² - m² - n² ⎞²
c = ⎜──────────────────────────⎟
        ⎝        2·l2          ⎠
```

**求解流程总结**：
1. 求出 `θ1` 角度（`sin θ1` 有 ± 两个根 → **对应肘部上/下两组解**，需按目标位置/连续性筛选）
2. 同理求出 `θ2`
3. 得到三个舵机角度 `θ1, θ2, θ3`，**根据角度控制舵机即可实现坐标位置的控制**

> 补充（这就是"多解"的直观来源）：`sin θ1` 的 ± 号给出两组解，再对 `θ2` 同样有±，理论最多 4 组（对应肩/肘 2×2）。实际选哪组由 MoveIt 的 IK 求解器按seed / 代价函数决定。
>
> 补充（与 MoveIt 的关系）：以上是**解析法（几何法）** IK。MoveIt 实际用的是**数值法**——KDL（`KDL::ChainFkSolverIkRec` 等）或 IKFast（把解析解离线生成 C++ 插件，速度快一个数量级）。解析法适合教学与固定机型快速实现；多自由度/带冗余自由度时解析解极难写，才落到数值迭代。

## 4. 机械臂坐标系介绍

三类坐标系，颜色约定**全课统一**：**绿轴 = X 轴，红轴 = Y 轴，蓝轴 = Z 轴**，**锥体位置为原点**。

### 4.1 基座坐标系（base_link）
- 位置：机械臂**基座**上。
- 原点：**底部舵机**位置。
- 绿 = X，红 = Y，蓝 = Z。

### 4.2 关节坐标系
- 机械臂本体两大组成部分：**旋转关节** 与 **连杆**。
- 关节坐标系在模型关节中展示，**每个关节一个**。
- 原点：**粉色锥体**位置；绿 = X，红 = Y，蓝 = Z。

### 4.3 工具坐标系（tool frame / end effector）
- 机械臂**末端**安装相应工具以满足不同工作需要；本机自带工具是**机械爪**。
- 原点：**锥体**位置；绿 = X，红 = Y，蓝 = Z。

> 补充（为什么这三类坐标系必须分清）：MoveIt 里三者对应 URDF 的 `base_link` / 各 `joint` 的子link origin / `tool0`（`kinematics.yaml` 里 `kinematics_solver` 的 `kinematics_solver_search_resolution` 与 TF 树 `base_link → ... → tool0` 必须对得上，否则 RViz 里拖动末端会"跳"或IK 报 `Frame` 错）。第6课截图中的末端**锥体+三色轴**就是 RViz 的 Interactive Marker 显示约定，与第7课第3 页截图里的拖动箭头是同一套可视化逻辑。

# 第7课 MoveIt 笛卡尔路径

## 1. MoveIt 笛卡尔路径介绍

### 1.1 笛卡尔坐标系
- 定义：**笛卡尔坐标系** = **直角坐标系**与**斜角坐标系**的统称。
- 相交于原点的两条数轴构成**平面仿射坐标系**；若两数轴上的**度量单位相等**，则称此仿射坐标系为**笛卡尔坐标系**。
- 两条数轴**互相垂直** → **笛卡尔直角坐标系**；否则 → **笛卡尔斜角坐标系**。
- 描述空间位置、速度、加速度时**大部分都用笛卡尔坐标系**。
- **绕某一个轴旋转多少角度，正方向用右手定则**（课件配图为三轴彩色手性示意图，X 红 / Y 绿 / Z 蓝 系的三维螺旋箭头）。

> 补充（手性/坐标系约定）：右手定则 + 叉乘 `X×Y=Z` 决定正方向。ROS 机器人学惯用 **X 前、Y 左、Z 上（FLU, Forward-Left-Up）**，与课件第 3 页截图里"绿=X 正方向=机械臂左边；红=Y 正方向=机械臂前方；蓝=Z 正方向=机械臂上方"**不一致**——那是 RViz 的显示配色（绿 X、红 Y、蓝 Z），不是 FLU 语义。**做笛卡尔直线插补时务必以 TF 实际坐标为准，别用颜色猜轴。**

### 1.2 笛卡尔路径规划
按**路径的性质**分为两类：
- **笛卡尔点到点（Cartesian point-to-point）路径规划**
- **笛卡尔连续路径（Cartesian continuous / linear）路径规划**

实现原理：**事先给定机械臂的目标点或者目标路径** → 通过**运动学计算**得到机械臂**关节层轨迹** → 实现期望路径的跟踪。

### 1.3 MoveIt 笛卡尔路径分析（为什么需要它）
- **关节空间**下：对每个轴分别控制，各轴变化都通过**插补**运动，**轴之间互相不关心其他轴如何运动** → 机械臂轴端在两个点之间走出的**轨迹是任意曲线**。
- **特殊情况**：要求机械臂**终端轨迹形状是直线或圆弧**等，即**对轨迹形状有要求**时 → 必须使用**笛卡尔路径规划**，**增加笛卡尔路径约束**。

> 补充（原理一句话）：MoveIt 的 `compute_cartesian_path` 在末端**笛卡尔空间**按`max_step`(e.g. 0.01m) 离散出N 个位姿点，每步**重新解 IK** 拼成关节序列，再交给时间参数化（如 TOTG）生成时间轨迹。因此只要**任一中间点 IK 失败或超出关节限位，整条路径就失败**——这是"Plan&Execute 失败"最常见的原因。

## 2. 仿真软件打开及实操

> ⚠️ **安全提示（课件原文，务必遵守）**：开始前，请确保机械臂周围**有足够的活动空间**，执行玩法期间与机械臂**保持一定的距离**，避免对人体产生误伤。
>
> 本节会给路径规划**增加笛卡尔路径约束**，**限制仿真模型和真实机械臂做线性运动**。

> ⚠️ **输入规范（课件原文）**：输入指令时需**严格区分大小写**，且可使用 **`Tab` 键补齐关键词**。

**步骤 1** — 将机械臂开机，并通过**"第3 课 MoveIt 配置"**下的**"环境搭建及建立连接"**内容，将机械臂与虚拟机建立连接。

**步骤 2** — 双击虚拟机系统桌面的图标（终端图标），打开命令行终端。

**步骤 3** — 打开一个新的命令行终端，输入：

```bash
roslaunch armpi_fpv_moveit_config demo.launch
```

启动 **MoveIt 工具**。

**界面分区（RViz + MoveIt 调试面板，课件截图标注）**：
- **① RVIZ 工具栏**（左下侧 Display 树：Global Options / Scene Geometry / Robot Description `armpi_description_pla…` / Status 等）
- **② MoveIt 调试区**（下方 MotionPlanning 面板，标签页：Planning / Manipulation / Scene Objects / Stored Scenes / Stored States / Status）
- **③ 仿真模型调节区**（右侧黑色视窗，绿色地面 + 3 个绿色目标/障碍物 + 彩色三轴箭头拖动手柄）

**步骤 4** — 找到 **"Planning"** 版块，**勾选 "Use Cartesian Path"**，开启笛卡尔路径规划。

**步骤 5** — 通过鼠标拖拽"仿真模型调节区"的**箭头**，规划机械臂的路径。
以机械臂为**第一视角**：
- **绿色 = X 轴**，正方向为**机械臂左边**
- **红色 = Y 轴**，正方向为**机械臂前方**
- **蓝色 = Z 轴**，正方向为**机械臂上方**

**步骤 6** — 规划完成后，点击 **"Plan & Execute"**。仿真模型会执行该动作，并**尝试在笛卡尔空间中线性移动末端执行器**；**如果该动作在笛卡尔路径约束下无法实现，则会显示失败**。

**步骤 7** — 如需关闭此玩法，可在终端界面按下 **`Ctrl + C`**。**若关闭失败，请反复尝试。**

### 课件明确写出的注意事项（逐条）

| # | 注意事项（课件原文） | 后果 / 解法 |

| 2 | 指令**严格区分大小写**，可用 **`Tab` 补齐 | `demo.launch` / `armpi_fpv_moveit_config` 写错就是 "Package not found" |

### 补充（工程必需，课件未展开但决定成败）：笛卡尔路径失败排查

| 现象 | 根因 | 解法 |
|---|---|---|
| 勾了 Use Cartesian Path 后 Plan 报错 | **该IK 求解器不支持笛卡尔路径** | MoveIt 源码里 `KDL` / `KDLP` 之类求解器对笛卡尔路径支持有限；改用 **IKFast** 或 `TRAC_IK`（支持位置/姿态容差与 reach-with-branching），在 `kinematics.yaml` 里替换 `kinematics_solver` |
| 走一点点就停、末端"卡"住不动 | **中途某点 IK 无解**（超出可达空间 / 关节限位 / 姿态歧义） | 缩小拖动距离、只拖 X 或只拖 Z；勾 **Collision-aware IK** 后重试；放宽关节限位或加 `joint_limits` 余量 |
| Plan成功但Execute 抖动 / 末端走弧线不是直线 | 未开笛卡尔约束，或中途IK 解跳到另一组解| 用**纯位置目标 + 姿态锁定**（`set_pose_reference_frame` / 位置目标而非姿态目标）；启用 `Avoidance Ratio`；必要时**先正解采样校验** |
| 末端出现跳变（Jump） | 两次求解得到的关节解不连续（跨过奇异或连杆翻转） | 保留上一次 IK 解作 **seed**（warm start）；降低笛卡尔步长 / 加姿态容差；减少目标点数量 |
| 提示笛卡尔步长过大 | `max_step` 太大 | 调小最大笛卡尔步长 / 加大插值分辨率 |
| 路径"卡在碰撞" | 笛卡尔直线穿过障碍物或自碰撞 | 勾 **Collision-aware IK**；调整障碍物/起终点；打开 RViz 碰撞检查看接触点 |
| 真实机械臂不动| 未切换到执行控制器 / 未连接 | 回到第3 课连接流程；确认 `/controller_manager` 已 spawn 控制器 |

> 课件外补充：术语对应关系（本课 RViz 勾选框 ↔ MoveIt API）：
> - Use Cartesian Path → `MotionPlanRequest::path_type = CartesianPath`
> - Collision-aware IK → `avoid_collisions = true`
> - Approx IK Solutions → `approximate_ik`（更快、可能非精确解）
> - Replanning → `replan`（跳变/失败时重规划）
> - Velocity/Accel Scaling → 时间缩放，对应 `execute_path(time_scaling)` 里的速度/加速度比例
> - Path Constraints: None → 本课**未使用**路径约束（`PathConstraints`：位置/朝向容差、抖动抑制、**比例缩放与跳变处理**属于这一层，是第10课及扩展的内容）

## 跨课串接：两课在 MoveIt 工作流中的位置

```
第6课 运动学设计（理论：DH / FK / IK 解析解 / 三类坐标系）
        ↓ 决定 URDF 的关节轴、原点、末端 frame 是否与理论一致
第3 课 MoveIt 配置（kinematics.yaml 选 IK 求解器 KDL/IKFast、生成 SRDF、碰撞矩阵）
        ↓
第5课 随机移动（关节空间点到点规划）
        ↓ 勾 Collision-aware IK
第7课 笛卡尔路径（＋笛卡尔约束：末端走直线，本课只讲勾选框）
        ↓ 想用代码复现 → 需 Path Constrains（比例缩放/跳变处理）+ execute_path
第10课 MoveIt 轨迹规划（时间参数化、TOTG、脚本化路径）
```

**一句话要点**：
- 第6课 → 关节空间里"关节角→末端位姿"的映射规则（DH 四参数 + 三类坐标系），以及逆解的多解本质（`sin θ = (-b±√(b²-4ac))/2a` 的 ± 号）。
- 第7课 →关节空间的插值不管末端轨迹形状；要末端走**直线/圆弧**，必须加**笛卡尔路径约束**，即在 MoveIt 中勾 **Use Cartesian Path**（RViz），工程上对应 `path_type = CartesianPath` + 逐点 IK 插补 + 每步碰撞检查。
