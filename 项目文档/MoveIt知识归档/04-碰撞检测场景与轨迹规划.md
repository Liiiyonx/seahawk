# 第8课 MoveIt 碰撞检测

## 1. MoveIt 碰撞检测介绍

### 1.1 碰撞检测配置介绍
- MoveIt2 中的碰撞检测使用 **`CollisionWorld` 对象**在**规划场景**中配置。
- 碰撞检测主要使用 **`FCL`** 软件包执行，**FCL 是 MoveIt2 的主要 CC（Collision Checking）库**。

### 1.2 碰撞对象介绍
MoveIt2 支持对不同类型对象做碰撞检测，包括：
1. **网格（Meshes）** — RViz 下拉里对应 `Mesh from file` / `Mesh from URL`
2. **基本形状（Primitive Shapes）** — 方盒、圆柱体、圆锥体、球体、**平面**（RViz 下拉：Box / Sphere / Cylinder / Cone / Mesh from file / Mesh from URL）
3. **Octomap** — Octomap 对象可直接用于碰撞检测（课件只列了名字，没展开；注意 RViz 的 Add/Remove 面板里**没有** Octomap 选项，Octomap 走的是 PointCloud → OctomapServer 通路，不在 Scene Objects 下拉里）

### 1.3 允许碰撞矩阵（ACM, Allowed Collision Matrix）
- ACM 编码一个**二进制值**，表示是否需要对物体（机械臂身上的，或机械臂世界中的物体）之间的碰撞进行检测。
- **ACM 中两物体对应值设为 1 → 不需要检测；否则需要检测。**（注意这个 1 的语义反直觉：1 = 允许碰撞 = 跳过检测）
- 本节目标：增加一个碰撞模型，演示仿真模型和真实机械臂碰撞检测的效果。

## 2. 启动 MoveIt 工具和执行

> 课件原文注意事项：
> - **输入指令时需严格区分大小写**，且可用 **Tab 键**补齐关键词。

# 第10课 MoveIt 轨迹规划

## 1. 轨迹规划器介绍

### 1.1 开源运动规划库（OMPL）
- OMPL 是**基于采样方法**的开源机械臂运动规划库（**基于 C++**），其内算法大多基于 **RRT 和 RPM** 衍生，如 **RRTStar、RRT-Connect** 等。
  （注：课件写 "RPM"，业界通用缩写是 **PRM**（Probabilistic Roadmap），此处按课件原文记录，疑为课件笔误。）
- 由于**模块化设计**、**前端 GUI 支持**、**稳定更新**，已成为最主流运动规划软件（**ROS 默认使用 OMPL**）。
- **基于采样方法**的规划方式**无需考虑规划目标的维度**，即**不会出现维度爆炸**，能有效解决高维空间和复杂约束下的路径规划问题——这是 OMPL 能用于 MoveIt 机械臂控制的关键原因。
- 对 **N 自由度**机械臂运动规划问题，OMPL 在**关节空间**内为末端规划一段轨迹：轨迹由 **M 个控制点（数组）**组成，**每个数组维度为 N**（每个控制点下的关节序列），且机械臂执行时**不与周围障碍物发生碰撞**。

### 1.2 工业运动规划器（Pilz）
- Pilz 是用于**圆周运动和线性运动**的**确定性**生成器。
- 支持使用 **MoveIt2 功能将多个运动段混合在一起**。
- （对应命令型规划器：PTP / LIN / CIRC）

### 1.3 运动规划随机轨迹优化（STOMP）
- STOMP 是一种**基于优化**的运动规划器，基于 **PI²（PI^2）算法**之上。
- 可为机械臂规划**平滑的轨迹**、避开障碍物并优化约束。
- **不需要梯度**，因此可以优化**成本函数中的任意项**。

### 1.4 基于搜索的规划库（SBPL）
- 一组**通用的运动规划器**，使用**基于搜索**的规划方法来**离散化空间**。

### 1.5 运动规划协变哈密顿优化（CHOMP）
- CHOMP 是一种新颖的**基于梯度**的轨迹优化程序，使许多日常运动规划问题既简单又可训练。
- 大多数高维运动规划器把轨迹生成**分为规划和优化两个不同阶段**；CHOMP 在优化阶段利用**协变梯度和函数梯度方法**，设计**完全基于轨迹优化**的规划算法。
- 在给定一个**不可行的初始轨迹**的情况下，CHOMP 会对周围环境做出反应，**以快速将轨迹从碰撞中脱离出来**，同时优化诸如**关节速度和加速度**等动力学量。该算法可**迅速收敛到一条平滑无碰撞的轨迹**，使轨迹可以在机械臂上**高效执行**。

> **本节特有注意事项（原文）**：
> - 开始前确保机械臂周围有足够活动空间，执行期间与机械臂保持距离，**防止机械臂碰撞到肢体发生损伤**。
> - **把天线向后弯折**，防止机械臂移动碰撞损坏到天线。（本课独有！第8/9课没有这条）
> - **本节程序集成了 OMPL 和 CHOMP 规划器，程序默认使用 OMPL 规划器**，下面会演示如何启动 CHOMP 规划器。
> - **注意：输入指令时需严格区分大小写**，可用 Tab 补齐。

## 4.2 ACM 碰撞矩阵配置（YAML）

**两种写法，按 MoveIt 版本选择：**

### 写法 A：矩阵形式（`<robot>_allowable_collisions.yaml`，Setup Assistant 生成，最常见）
```yaml

  - [base_link, base_link, true]
```

```yaml

  - [finger_link1, finger_link2] # 夹爪闭合时两指接触，必须允许
  - [tool_link, workpiece]      # 加工必然接触

  - [base_link, floor, true]
  - [finger_link1, finger_link2, true]
  - [tool_link, workpiece, true]
```

### 写法 B：SetPair 式（代码里动态改）

### 用 Setup Assistant 图形化生成（强烈推荐，别手改）
```bash

```
- **Self-Collisions** 页 → 调 sampling density（默认 10000 次随机位姿自碰撞检查，**建议拉满**以免误禁）→ `Generate Collision Matrix`

```python
# ---------- 4. 删物体 ----------

# ---------- 5. 附加碰撞体（attach：物体变成末端的一部分） ----------
#    关键：必须给 touch_links，否则规划器认为末端一直撞着物体，永远规划不出抓取动作

#    attach 之后物体从 known_objects 列表消失（变成 attached object）

def wait_for_scene_update(obj, attached, timeout=5.0):
    t0 = rospy.get_time()
    while rospy.get_time() - t0 < timeout:
        is_known = obj in scene.get_known_object_names()
        is_attached = obj in [o.name for o in scene.get_attached_objects(eef).values]
        if is_attached == attached and is_known == is_known_expected:
            return True
        rospy.sleep(0.1)
    return False

rospy.sleep(2.0)   # 实操中最省事的做法
```

1. **Pre-processing adapters**（改请求）→ **Motion Planner**（生成几何路径）
2. **Post-processing adapters**（改响应，主要是加时间戳）→ **Trajectory Execution / Controller**

| post | `AddRuckigTrajectorySmoothing` | **jerk（加加速度）限幅** | 硬件怕冲击 / 末端抖动 |

## 4.5 时间参数化 & 轨迹平滑 & jerk

**核心认知**：MoveIt 本质是**运动学**规划框架 —— 只规划关节位置或末端位姿，**不规划速度/加速度**。时间参数化是**后处理**，给空间路径加上时间戳、速度、加速度。

**关节限值来源**：URDF 或 `config/joint_limits.yaml`（Setup Assistant 生成，初值是 URDF 的精确拷贝）。
```yaml
# config/joint_limits.yaml
joint_limits:
  joint1:
    has_velocity_limits: true
    max_velocity: 3.14       # rad/s
    has_acceleration_limits: true
    max_acceleration: 3.14   # rad/s^2
    has_jerk_limits: true
    max_jerk: 10.0           # rad/s^3
```
可用键：`max_position / min_position / max_velocity / max_acceleration / max_jerk`；
开关：`has_velocity_limits / has_acceleration_limits / has_jerk_limits`。

**运行时缩放**（RViz Planning 面板里的 `Velocity Scaling` / `Accel. Scaling`，见课件截图，默认都是 1.00）：
- 取值 0–1，作为 `MotionPlanRequest.max_velocity_scaling_factor` / `max_acceleration_scaling_factor`。
- **不缩放 = 1.00**，会贴着限值跑，真机慎用。

**三种时间参数化算法：**

| 算法 | Adapter | 特性 | 适用 |
|---|---|---|---|
| **IPTP** Iterative Parabolic Time Parameterization | `AddTimeParameterization`（旧默认） | 等距插补，速度/加速度平滑，但**无法避免加速度抖动**；有已知 bug | 老系统兼容 |
| **ISP** Iterative Spline Parameterization | `AddIterativeSplineParameterization` | 反复拟合三次样条，位置/速度/加速度连续且在界内，**jerk 不连续**；限值执行更严格 → 同样限值下**轨迹更长** | 从 IPTP 迁移需**放宽限值** |
| **TOTG** Time-Optimal Trajectory Generation | `AddTimeOptimalParameterization` | **MoveIt 2 全局默认**。把路径段拟合到原轨迹再采样新路点，速度曲线非常平滑连续；**输出为等时间间距**；因路点可能在容差内偏离原轨迹，**可能需要额外碰撞检查** | 默认首选 |

**jerk 限幅（额外后处理）：**
- TOTG 只处理速度和加速度，**所有时间参数化算法都不支持 jerk 限幅**。大 jerk 会导致机械臂抖动或损伤硬件。
- 解法：**Ruckig** jerk-limited smoothing 插件。
```yaml
request_adapters:
  - default_planner_request_adapters/AddRuckigTrajectorySmoothing   # 必须放最前（最后执行）
  - default_planner_request_adapters/AddTimeOptimalParameterization
```
- 前置条件：`joint_limits.yaml` 里**必须定义 `max_jerk`**；若未定义会套用合理默认值并打印警告。

**TOTG 时间间距的坑**：默认 0.1s；过小（如 0.001s）会出现运动不恒定、速度不平滑；**~0.005s** 较稳定（需与控制器输出频率匹配）。

## 4.6 规划器选型对照

| 规划器 | 类型 | 特点 | 什么时候用 |
|---|---|---|---|
| **OMPL**（RRTConnect） | 采样 | ROS 默认；非确定性（每次路径不同）；需后处理时间参数化 | 通用关节空间规划、复杂工作空间、pick-and-place |
| **RRTstar / BITstar** | 采样+最优 | 渐进最优，路径质量更好 | 对路径平滑度/长度有要求 |
| **Pilz**（PTP/LIN/CIRC） | 确定性 | 笛卡尔指令；严格速度/加速度廓形；**LIN 要求整条直线无碰撞** | 焊接、涂胶、装配直线段、可复现性要求高 |
| **CHOMP** | 梯度优化 | 快速脱离碰撞、轨迹平滑；**对初始轨迹质量敏感** | 已知工作空间、追求平滑；在 OMPL 找到可行种子之后用 |
| **STOMP** | 随机轨迹优化（PI²） | 平滑、避障、**无梯度**可优化任意成本项 | 需要平滑运动、多目标优化 |
| **SBPL** | 基于搜索 | 离散化空间 | 栅格类场景 |

## 4.7 坑 / 注意事项 / 常见报错与解法

### 课件里明确的坑
1. **命令区分大小写**，用 **Tab** 补齐（三课都写了，说明踩过）。
2. **终端 Ctrl+C 关闭可能失败，需反复尝试**（三课都写了）。
3. **第10课独有：必须把天线向后弯折**，否则机械臂运动撞坏天线。
4. **第8课：碰撞模型建议缩到初始尺寸 50%**，否则容易一开始就穿插，规划不出解。
5. **规划目标位置若为红色（自碰撞），该动作无法执行**，必须调回无碰撞状态。
6. **第9课：物体改完位置必须点 `Publish`**，否则 MoveIt 收不到，场景不会更新（"我明明拖了它怎么没动"）。
7. **执行真机前把机械臂周围清空并保持距离**（防误伤）。
8. **第8课与第9课的模型默认生成位置不同**（底部 vs 场景中心）——迁移操作时容易懵。

### 官方/工程侧常见坑
9. **"You have local changes to your planning scene. Publish them to the move_group node?"** — 选 **No** 会导致场景物体不生效、规划仍穿模。选 **Yes**。
10. **`Start state in collision` 报错** — 加 `FixStartStateCollision` adapter（小幅扰动找无碰撞起点），或清掉场景里残留的旧碰撞体。
11. **`No plan found` 但路径明显可达** — 多半是起始或目标状态自碰撞。看 `/move_group/display_grasp_markers` 或开 RViz MotionPlanning 的 Debug 显示 OMPL 采样点。放宽目标容差。
12. **随机出现"总是碰撞" / "从不碰撞"** — ACM 过期。**URDF 改过就必须重跑 Setup Assistant**。
13. **规划路径穿过机器人自己** — ACM 把某对 link 误标成"永不碰撞"。重新生成。
14. **小距离目标只规划出 1 个 waypoint，机械臂不动** — 调 `ompl_planning.yaml`：
    ```yaml
    default_planner_config: RRTConnectkConfigDefault
    planner_configs:
      - RRTConnectkConfigDefault
        longest_valid_segment_fraction: 0.005   # 默认 0.01；调小 = 采样更密 = waypoint 更多
    ```
    注意 waypoint 过多 → 控制器拒绝（时间戳相同/过密）。
15. **`Trajectory execution failed`** — 控制器跟不上规划轨迹，通常是 URDF 里的速度/加速度限值对真机太激进。改 `joint_limits.yaml`。
16. **轨迹不连续 / 缺点** — 可能是缺时间参数化；或在 plan 前没 `set_start_state_to_current_state()`。真实机器人当前关节状态与轨迹首点误差必须在容差内，否则 `execute()` 直接失败。
17. **OMPL 路径"钻穿"薄障碍** — `longest_valid_segment_fraction` 太大（碰撞检测采样太稀）。减小它。
18. **`Goal pose unreachable`** — IK 求解失败：目标点在工作空间外，或 IK 插件限制太严。试 TRAC-IK / KDL，调 `kinematics_solver_search_resolution` 与 `kinematics_solver_timeout`。
19. **IPTP→TOTG 迁移后轨迹变长** — TOTG/ISP 限值执行更严格，同样限值下耗时更长。适当放宽限值。
20. **Ruckig 没生效** — 忘了配 `max_jerk`，或没把 `AddRuckigTrajectorySmoothing` 放在 adapter 列表**最前**。
21. **`Projection_evaluator` 不能瞎填** — 决定 OMPL 如何投影距离。双臂系统应选左右臂各一个肩关节；只填单臂关节会导致规划路径绕大圈。
22. **mesh 碰撞检测慢** — 视觉网格应替换为简化的碰撞网格；重 mesh 可考虑换 Bullet 替代 FCL。
23. **Octomap 把整片地板当障碍** — 必须开 `filter_ground_plane`，并按地面平整度调 `ground_plane_distance`（默认 0.015m）。
24. **改完 YAML 不生效** — `ompl_planning.yaml` 等配置是**启动时加载**的，必须重启 `demo.launch`。
25. **`add_*` 后物体没出现** — Python 节点在碰撞体更新消息发出前就退出了，消息丢失。add/remove/attach/detach 之后都要等 `get_known_object_names()` / `get_attached_objects()` 反映出来。
26. **Python 节点在规划中途死掉** → 场景里物体残留（"幽灵障碍物"）。用 `timeout` 键（`"id": {"timeout": {}}`，`timeout: 0.0` = 永不过期）显式设置，或在节点退出时清理。

## 4.8 RViz MotionPlanning 面板 ↔ 脚本 API 对照（复用速查）

| RViz 面板元素 | 脚本 API |
|---|---|
| Planning Group: `arm` | `MoveGroupCommander("arm")` / `moveit.get_planning_component("arm")` |
| Start State: `<current>` | `arm.set_start_state_to_current_state()` / `arm.set_start_state(pose_msg)` |
| Goal State: `home` | `arm.set_named_target("home")` / `arm.set_pose_target(pose)` / `arm.set_joint_value_target(list)` |
| Start/Goal State: `<current>` + Joints 面板拖滑杆 | 直接设 `robot_state = arm.get_current_state().robot_state` 或 `arm.get_current_joint_values()` |
| Planning Time (s): 5.0 | `arm.set_planning_time(5.0)` |
| Planning Attempts: 10 | `arm.set_num_planning_attempts(10)` |
| Velocity Scaling: 1.00 | `MotionPlanRequest.max_velocity_scaling_factor` |
| Accel. Scaling: 1.00 | `MotionPlanRequest.max_acceleration_scaling_factor` |
| **Collision-aware IK** | `arm.set_planner_id(...)` 无对应；控制 `PlanningScene` 的 ACM + `check_collision` / `PlanningRequest` 的碰撞检测开关 |
| Approx IK Solutions | `MotionPlanRequest.planner_id`（允许近似 IK 解） |
| Use Cartesian Path | `arm.compute_cartesian_path(waypoints, eef_step, jump_threshold)` |
| Replanning | `arm.allow_replanning(True)` / `MotionPlanRequest.replan` |
| External Comm. | `MotionPlanRequest.external_communication` |
| Path Constraints: None | `arm.set_path_constraints(Constraints())` |
| [Plan] | `plan_result = arm.plan()` |
| [Execute] | `move_group.execute(plan_result)` / `arm.execute(plan_result.trajectory)` |
| [Plan & Execute] | `arm.go()` |
| [Stop] | `arm.stop()`（`moveit.stop()`） |
| [Clear octomap] | `planning_scene.clear_octomap()` |
| Clear octomap 后的 `Time: 0.253` | 规划耗时（秒） |
| Show Trail (Planned Path) | 需自行 `moveit_msgs/DisplayTrajectory` 发到 `/move_group/display_planned_path` |
| Scene Objects → Publish | `planning_scene` 的 `apply_*` / `move_group` 的 `/planning_scene` 话题 |
| Scene Objects → Export / Import | `planning_scene.write_scene()` / 读入场景文本 |

## 4.9 规划执行完整流程模板（照着改就能跑）

```python
#!/usr/bin/env python
# -*- coding: utf-8 -*-
import sys, rospy
import moveit_commander
from moveit_commander import MoveGroupCommander, PlanningSceneInterface, RobotCommander
from geometry_msgs.msg import PoseStamped

moveit_commander.roscpp_initialize(sys.argv)
rospy.init_node("lesson8_10_rehearsal", anonymous=True)

robot = RobotCommander()
scene = PlanningSceneInterface()
arm   = MoveGroupCommander("arm")
eef   = arm.get_end_effector_link()
rospy.sleep(1.0)

# 1) 场景：清残留 → 加障碍物 → 等生效
scene.remove_world_object("obstacle_box")
p = PoseStamped(); p.header.frame_id = "base_link"; p.pose.orientation.w = 1.0
p.pose.position = (0.35, 0.0, 0.30)
scene.add_box("obstacle_box", p, size=(0.10, 0.10, 0.10))
rospy.sleep(2.0)   # 关键：等 move_group 收到

# 2) 规划参数（对应 RViz Planning 面板）
arm.set_planning_time(5.0)
arm.set_num_planning_attempts(10)
arm.allow_replanning(True)
arm.set_goal_position_tolerance(0.01)
arm.set_goal_orientation_tolerance(0.05)

# 3) 起始 → 目标
arm.set_start_state_to_current_state()
arm.set_named_target("home")

# 4) Plan（先只规划，不执行 —— 对应 RViz 的 Plan）
plan = arm.plan()
if plan and plan.success:
    arm.execute(plan, wait=True)   # 对应 Execute
else:
    rospy.logerr("规划失败")

moveit_commander.roscpp_shutdown()
```

## 一页速记

- **三课唯一命令**：`roslaunch armpi_fpv_moveit_config demo.launch`（区分大小写，Tab 补齐，Ctrl+C 可能需反复按）
- **界面三区**：① RViz 工具栏 ② MoveIt 调试区 ③ 仿真模型调节区
- **三色箭头**：绿=X(左) 红=Y(前) 蓝=Z(上)
- **状态颜色**：橙色=可执行；红色=自碰撞，无法执行
- **ACM 语义**：`1/true` = 允许碰撞 = **跳过**检测（反直觉）
- **规划组名**：`arm`；5 关节 `joint1..joint5`；named state `home`
- **碰撞检测**：CollisionWorld + FCL；对象=Mesh / 基本形状 / Octomap
- **五种规划器**：OMPL(默认，RRT/RRTStar/RRTConnect) / Pilz(确定性 PTP·LIN·CIRC) / STOMP(PI² 无梯度优化) / SBPL(搜索离散化) / CHOMP(协变梯度优化)
- **时间参数化**：MoveIt 只规划位置 → TOTG(默认) 加时间戳/速度/加速度；**jerk 需 Ruckig**（配 `max_jerk` + adapter 放最前）
- **改场景必 Publish / 改 YAML 必重启 launch**
