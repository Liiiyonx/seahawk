## 0. 先给结论

本子系统把机械臂执行端从「厂商远程桌面观测窗」升级为「自带现场再训练能力的自主作业端」。

现状：机械臂入口是 `nx://` 协议唤起 NoMachine 远程桌面（ArmSimConsole 脚注原文：「不走平台 MQTT 闭环」），证据级别 E2 受控实验；厂商演示程序（face_detect 等）依赖预设初始位姿与固定关节序列回放；平台无法向机械臂下发作业指令，也没有任何现场模型适应能力。

目标链路（一条线讲完）：操作员与树莓派组网（STA 同网为主、热点直连兜底）→ 平台工单看板派单，MQTT 下发 `robot/{id}/task`，树莓派回 ACK → 操作员在工单详情点「打开机械臂作业台」，输入 IP（默认 `192.168.149.1`），浏览器进入树莓派上的训练作业台页面 → 页面完成「采集 → 标注 → 训练 → 验证」四步，模型精准识别塑料袋并对彩色浮标显式免疫 → 点「开始作业」，抓取智能体全自动闭环拾取，全程 IK 实时解算、无预设动作序列 → progress 实时回传，工单在平台闭环。

投入结构：平台侧后端**零改动**（MQTT 契约现成），前端仅改 ArmSimConsole 与入口文案；机械臂侧复用厂商 ROS 工作空间（IK 解算、总线舵机控制、相机话题），新建三个组件（grasp_web / grasp_agent / vision）。

本计划书当前证据级别 **E0**（方案已定，待实施）。按四阶段推进，每阶段有独立可判定的验收标准，完成即分别达成 E1（链路）、E2（训练闭环）、E2→E3（真机抓取闭环）、E3（平台联调整体演示）。

## 2. 目标与需求

### 2.1 总目标

在 ArmPi FPV 真机上实现「平台派单联动 + 现场自适应训练 + 浮标免疫 + 全自动无预设拾取」的完整闭环，并纳入平台演示动线，作为「软硬闭环」章节的真机升级版证据。

### 2.2 核心需求

| 编号 | 需求 | 判定标准（可验收） |
| --- | --- | --- |
| R1 | 组网直连：树莓派 STA 接入演示网（主），热点 AP 直连（兜底） | 演示笔记本浏览器可打开 `http://<IP>:8090` 作业台页面；两种模式均演示过一次 |
| R2 | 工单联动：平台派单经 MQTT 到达树莓派，作业台显示工单上下文，作业 progress 回传平台 | 平台工单状态随真机作业推进而变化；progress 主题有真实报文 |
| R3 | 现场再训练：作业台页面完成采集→标注→训练→验证→部署全流程，无需 SSH 进终端 | 现场采集 ≤300 帧、页面完成标注与训练、部署后实时画面检测框符合预期；全程只在浏览器操作 |
| R4 | 浮标免疫：彩色浮标在画面内时机械臂只抓塑料袋 | 连续 10 次作业，浮标零误抓；实时画面中浮标仅显示为灰色忽略框 |
| R5 | 全自动无预设：所有动作由感知输出→IK 实时解算产生，无任何录制的关节序列 | 代码审查无固定脉宽序列回放；同一套逻辑在场景中袋位随机放置时均能抓取 |

### 2.3 范围边界（明确不做）

- 不改造机械臂本体、不加装深度相机（单目 + 9 点标定 + 平面假设够用）。
- 不改平台后端任何代码（MQTT 契约零改动是本方案的架构卖点）。
- 不做水上自主航行与动态目标跟踪（固定工位、静态或缓动水面场景）。
- 不建生产级 MLOps 平台（轻量版本化 + 留出集评估 + 一键回滚即可）。
- 不承诺生产级精度指标（演示与受控实验口径，对外表述遵守总控计划书证据分级纪律）。

## 3. 总体技术方案

### 3.1 架构总览

```text
┌─────────────┐         ┌──────────────────────────────────┐      ┌────────────┐
│ Oceanus 平台 │  MQTT   │        树莓派 · ArmPi FPV          │      │   真机硬件  │
│             │◄───────►│  :8090 训练作业台（新建·焦点）       │      │            │
│ 工单派单     │ 契约复用 │    采集→标注→训练→部署             │      │  FPV 相机   │──┐
│ 任务看板     │ 零改动   │  感知模型 YOLOv8n {袋, 浮标}       │◄─────┤            │  │图像流
│             │         │  抓取智能体（ROS·新建）             │─────►│  机械臂     │◄─┘
└──────┬──────┘         │    视觉伺服·IK·状态机              │      │  舵机·夹爪  │
       │▲ 派单/回执      └──────────────────────────────────┘      │  塑料袋+浮标 │
       │└──────────── 组网：STA 同网（主）/ 热点直连（兜底）         └────────────┘
┌──────┴──────┐
│ 操作员·笔记本  │── 输入 IP → 浏览器直连树莓派作业台（操作主线）
└─────────────┘
```

三个关键架构决策：

1. **新页面跑在树莓派上，不在平台里。** 「输入 IP 跳转」的本质是浏览器直连树莓派（FastAPI，`:8090`），数据采集、训练、部署、作业控制全部在 Pi 本地闭环，平台只做入口与看板。
2. **组网选 STA 为主。** 已验证 AP 直连独占网卡、演示电脑无法同时访问平台（ArmSimConsole 排障提示原文）；STA 同网时 MQTT 工单闭环与训练页同时可用，且演示笔记本可作为局域网协同训练算力。AP 直连作为独立兜底模式（页面显示离线缓存工单）。
3. **MQTT 契约零改动。** `robot/{robot_id}/task`、`robot/{robot_id}/cmd/ack`、`robot/{robot_id}/task/progress` 三主题现成；树莓派侧仅新增一个 MQTT 客户端桥接到 ROS。

### 3.2 组网模式

| 模式 | 用法 | 平台闭环 | 训练算力 | 定位 |
| --- | --- | --- | --- | --- |
| STA 同网 | 树莓派接入演示网 | 可用 | 可用局域网协同训练 | **演示主模式** |
| AP 热点直连 | 笔记本连 `192.168.149.1` | 断开（页面显示离线缓存工单） | 仅 Pi 本地 | 独立兜底 |

### 3.3 MQTT 接口契约（复用，零改动）

| 方向 | 主题 | 载荷要点 |
| --- | --- | --- |
| 平台 → 树莓派 | `robot/{robot_id}/task` | `command_id = cmd_{task_id}`、`action=dispatch`、`params.task_id/target/priority`（与 `build_dispatch_payload` 一致） |
| 树莓派 → 平台 | `robot/{robot_id}/cmd/ack` | 任务确认，幂等键同 `command_id` |
| 树莓派 → 平台 | `robot/{robot_id}/task/progress` | `{task_id, phase, item_count, ts}`，作业阶段实时回传 |

凭证沿用现有 `robot_device` 通道配置（见部署环境变量），不在本文书明文。

## 4. 模块设计

### 4.1 训练作业台（`grasp_web/`，新建，FastAPI :8090）

页面为单页应用（PC 端构建后部署到 Pi，不在 Pi 上跑构建链），六个区块：

| 区块 | 功能 | 接口 |
| --- | --- | --- |
| 工单上下文 | 显示 MQTT 收到的工单号、目标、优先级（`?task_id=` 透传） | `GET /api/task` |
| 实时画面 | MJPEG 视频流 + 检测框叠加（塑料袋=高亮框，浮标=灰色忽略框） | `GET /stream` |
| 数据采集 | 一键连拍 150–300 帧，机械臂自动换 3–4 个观测姿态增广视角 | `POST /api/capture` |
| 标注台 | 现模型预标注 + 浏览器画框修正；浮标标为 `buoy` 类 | `POST /api/label` |
| 训练任务 | 选择档位后台训练，SSE 推进度与 loss | `POST /api/train` |
| 部署验证 | 留出集评估达标才允许切换；权重版本化，一键回滚 | `POST /api/deploy` |

作业控制：`POST /api/grasp/start|stop`。所有接口只在本机/局域网暴露，不鉴权上公网。

### 4.2 感知模型（`vision/`，新建）

| 项 | 决策 | 理由 |
| --- | --- | --- |
| 底座 | YOLOv8n，输入 320×320，NCNN 运行时 | Pi 4 CPU 约 3–5 FPS；总线舵机动作慢，200–300ms 伺服周期足够 |
| 类别 | `{plastic_bag, buoy}` | 浮标是**显式负类**而非背景——「认得出、绝不动手」 |
| 数据配方 | 150–300 帧；浮标必须在场（硬负样本来源）；覆盖反光/距离/遮挡；离线增广 ×3 | 抗干扰能力来自样本分布，不来自事后补丁 |
| 部署安全 | 留出集评估 mAP 达标才允许切换；权重按版本落盘；一键回滚上一版 | 演示日翻车的最后防线 |

训练档位（应对 Pi 算力现实，页面上三档可选）：

| 档位 | 做法 | 量级 | 用途 |
| --- | --- | --- | --- |
| 免训练校准 | 只调置信度阈值 + ROI 屏蔽 + HSV 滤波 | 秒级 | 演示日兜底保险 |
| Pi 本地微调 | 冻结骨干只训检测头，~30 epoch | Pi 4 约 30–60 分钟 | 标配，后台执行 |
| 局域网协同 | 演示笔记本跑 ultralytics 全量微调，权重回传 Pi | 分钟级 | 推荐主路径（STA 模式下笔记本本就连着同网） |

### 4.3 抓取智能体（`grasp_agent/`，新建 ROS 节点）

状态机六状态，全闭环：

| 状态 | 动作 | 失败出口 |
| --- | --- | --- |
| ① 持续检测 | YOLO 实时推理，输出候选 | — |
| ② 目标锁定 | 三层过滤后锁定唯一目标（轨迹 ID） | 无候选→继续检测 |
| ③ 视觉伺服逼近 | 眼在手上，边走边重检测修正 | 跟丢→回① |
| ④ 精准夹取 | IK 解算到抓取点，夹爪渐闭至舵机位置停滞（夹到即停） | 不可达→回① |
| ⑤ 抓取验证 | 原位置目标消失 + 夹爪位置差双证据 | 验证失败→回①重试 |
| ⑥ 放置入槽 | 移到臂座旁边料槽的示教/配置点（`coord` 走 IK，`pose` 回放单点示教位），松爪落料 | 未示教→拒开工；不可达→就地松爪并如实上报 |

工程约定：

- 沿用厂商 `enter / exit / set_running / heartbeat` ROS 服务模式，与厂商程序共存、不抢串口。
- 复用 `ik_transform.ArmIK` 与 `bus_servo_control.set_servos`，不重写运动学。
- 作业过程持续回填 `t_track.servo_telemetry`（舵机回读），保持 ArmSimConsole 遥测面板有真数据。

## 5. 关键技术决策

### 5.1 浮标免疫三层防线

| 层 | 机制 | 作用 |
| --- | --- | --- |
| 训练层 | 浮标作显式负类参与训练（硬负样本挖掘） | 特征层面分开袋与浮标 |
| 推理层 | 仅 `plastic_bag` 且置信度 ≥ 阈值才进入抓取候选 | 浮标即使被检出也不触发 |
| 决策层 | HSV 饱和度校验（浮标高饱和、袋白/半透明低饱和）+ 轨迹 ID 锁定 | 最后兜底，抗误检 |

HSV 只作决策层辅证，不单独决策——水面反光会破坏颜色稳定性，主判据始终是模型类别。

### 5.2 「无预设动作」的实现口径

与厂商 demo 的本质区别：

| 项 | 厂商 face_detect | 本方案 |
| --- | --- | --- |
| 初始位姿 | `initMove` 固定脉宽 | IK 计算的待命位（同一函数、参数来自标定，非录制值） |
| 动作执行 | `move()` 内写死的关节序列回放 | 感知输出 → IK 实时解算 → 舵机 |
| 夹爪 | 固定脉宽开合 | 渐闭 + 舵机位置回读停滞检测（自适应袋大小） |
| 放置点 | 无 | 固定工位示教/配置一次（料槽焊在臂座旁，不是每帧现算；AprilTag 若后续加装再换成视觉定位） |
| 失败处理 | 无 | 验证 → 重试 → 超限上报 |

「预设动作」在本方案中指「录制的关节序列回放」；IK 计算得到的位姿（如安全待命位）不属于预设动作。对外表述按此口径，防止被评委问穿。

### 5.3 像素→工作区坐标：一次性 9 点标定

作业台引导流程：机械臂按 IK 走到工作平面 9 个已知点 → 记录各点相机像素坐标 → 拟合单应/仿射映射 → 存标定文件。FPV 相机装在臂上（眼在手上），逼近过程中持续重检测修正，标定误差由闭环逐帧吸收。

### 5.4 场景与抓取策略

- 抓取点取检测框下沿中心（袋口），夹爪大开口慢闭，降低形变目标滑脱率。
- 工作半径收窄到标定区内（约 20cm 半径），规避总线舵机 ±0.5cm 重复精度的影响。
- 水面场景注意：相机俯角避开镜面反射带；训练集强制覆盖反光样本。

## 6. 实施计划（四阶段）

每阶段独立可验收，验收不通过不进入下一阶段。

### 阶段一：链路验证

| 项 | 内容 |
| --- | --- |
| 目标 | Pi 起 Web 服务，视频流进浏览器，页面可手动点动机械臂 |

### 10.1 已落地并验证

### 10.2 模型实测（第三方公开基准，非现场数据）

| 项 | 结果 |
| --- | --- |
| 数据集 | SC-FloatWaste，官方划分 train 600 / val 172 / test 400；构建为单类 `plastic_bag`（塑料框 6,846，另 218 张纯背景负样本） |
| 训练 | 两版：v1（litter 权重续训，28 轮早停）/ **v2（`yolo11s` 起训，768 分辨率 120 轮，最优第 100 轮）** |
| 独立测试集评测 | v1 `mAP50@416 = 0.382`；**v2 `mAP50@416 = 0.423`**（768 上 0.494），P 0.512 / R 0.498 |
| 部署产物 | `edge/grasp/models/active/best.onnx`（36MB / opset12 / 416），版本 `v20261015_102048`，含测试集指标元数据 |
| 加载与推理验证 | 作业台检测后端 = `onnx`；真实测试图检出塑料袋 conf 0.74–0.93 |

**口径**：以上均为**公开数据集上的精度**，非连江现场、非本项目设备实测；
数据集为河流漂浮垃圾，现场为海水养殖区（含鲜艳彩色浮标），存在域差异。
对外表述必须回到 `docs/competitions/public-floatwaste-benchmark.md` 的口径纪律。

### 10.3 实施中修掉的缺陷（现场会翻车的那类）

1. **部署版本号秒级碰撞** —— 同一秒两次部署会撞同名目录并覆盖上一版权重，历史写脏。改为 `mkdir(exist_ok=False)` 抢名 + 序号重试。
2. **`_activate()` 每次追加历史** —— 回滚一次就多出一条重复版本记录（`versions()` 与 history 条数不符，页面出现幽灵版本）。改为只在 `deploy` 登记。
3. **无相机时页面永久卡死** —— 非 mock 且 ROS 未起时 `/stream` 不产出任何字节，`<img>` 永远加载中、浏览器 `load` 事件不触发。已加无信号占位帧。
4. **作业台在 ROS 不可用时整体崩掉** —— 现场最常见故障。已改为服务照常启动，状态接口暴露 `ros_error`，页面显示红色排障胶囊（模型加载与硬件就绪解耦）。
5. **标注口径与部署模型口径打架** —— `classes` 被标注台与检测器共用（标注台需 `buoy` 负类，部署单类模型只输出 `plastic_bag`）。已拆成 `classes` / `model_classes`。

### 10.4 尚未完成（依赖真机）

阶段一~三的**真机验收**（点动、标定、抓取闭环）与阶段四**平台联调**仍需硬件到位；
`edge/arm_bridge/config.yaml` 的 `backend` 仍保留 `simulated`，接机后切换为
`oceanus_vision` 即启用。上真机前必须核对配置中标注「需真机核对」的夹爪脉宽，
并完成 9 点标定。
