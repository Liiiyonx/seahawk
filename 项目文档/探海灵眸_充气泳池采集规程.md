# 探海灵眸 · 充气泳池第一人称采集规程

> 目的：为「机械臂第一人称视角下识别水面塑料袋」生产**高精度**训练数据。
>
> 证据口径：充气泳池属**受控环境**，对应清单机制里的 `data_type: quasi_real`、
> `evidence_level: E2`（见 `ml/datasets/manifests/README.md` §4）。**不得写成 E3/E4**。
>
> 为什么必须自采：公开集里与「水面 + 塑料袋」相关的几乎全是航拍 / 3m 高俯拍，
> 与本机「相机装在夹爪上、离水面 8~20cm 第一人称俯视」差距极大。这一条是本项目
> 已有教训（公开岸基俯拍数据保不住机械臂视角精度），也是本次精度的**唯一**来源。

---

## 一、场景布置（动手前逐项确认）

| # | 项 | 要求 | 为什么 |
|---|---|---|---|
| 1 | 泳池 | 充气泳池注水，静置消泡后再采（刚注满时水面波动大、反光乱） | 波纹/反光是主要干扰，要可控 |
| 2 | 目标 | **白色/半透明塑料袋**，不用黑袋、不用彩色袋 | 演示域袋色是低饱和白/灰；黑/彩色是域外且易与浮标混淆 |
| 3 | 底衬 | 池底铺**深色**（黑/深蓝）垫布 | 深水色最能压住反光，也让白袋高对比 |
| 4 | 光照 | 均匀补光，避免顶灯直射造成镜面高光；同时**必须**拍若干张有高光的 | 高光下模型要能分清"反光"和"白袋" |
| 5 | 相机离水面 | **8~20cm**（这是夹爪工作高度，别为了好看抬高） | 高度决定真实域，抬高就白采 |
| 6 | 臂姿态 | 低头观测位：`pitch=-175`（近垂直朝下），与闭环 `observe_look_down` 一致 | 采什么姿态，现场就什么姿态 |
| 7 | 参数 | 原生 **640×480**，不缩放、不压缩重编码 | 与部署输入口径一致 |
| 8 | 现场 | 采集时**人不要在画面里**（除非专门采"手入画"负样本） | 手是最强干扰源 |

## 二、正样本：塑料袋（400~800 帧）

每个维度都要覆盖，不要只拍一种：

| 维度 | 取值 |
|---|---|
| 位置 | 池心 / 池边 / 近（画面下缘）/ 远（画面上缘）/ 左 / 右 |
| 形态 | 团状、铺开、半浸没、袋口朝上、袋口朝下、被水膜覆盖 |
| 数量 | 单袋为主；另拍少量**多袋**帧 |
| 光照 | 均匀光、侧光、有高光、略暗 |
| 运动 | 静止为主；少量水面微波导致袋体轻微漂移的帧 |

## 三、负样本（400~600 帧）—— 决定精确率，**不许省**

机械臂场景误抓代价高，负样本比正样本更值钱。必须逐类拍：

1. **空池**：只有水与底衬（各种角度、各种光照）
2. **水面干扰**：波纹、泡沫、反光带、池壁倒影、水面漂浮的碎屑/落叶
3. **池体与周边**：池壁、池沿、地面、水管的入水口
4. **臂体自己（最高优先）**：让夹爪/腕部/线缆进入画面各区域（这是现场实测
   被误检成塑料袋 `conf 0.85`、且为全场最高的那个来源）
5. **手入画**：手把袋子放进水里的过程帧
6. **其他漂浮物**：瓶盖、瓶、泡沫块、树叶（若现场有）

> ### ⚠️ 纯负样本组必须标「背景」，否则会被静默丢掉
>
> 规程说负样本「整张不标」，但组装训练集时 `Dataset.labeled_frames()` 只收**标注非空**
> 的帧（那是为了不把"还没标"的帧误当负样本）。两者叠加的后果是：空池、臂体入画这些
> **最值钱的负样本会被当成"尚未标注"整组剔除**，模型照样在臂体上误检。
>
> `edge/grasp/tools/capture_pool.py` 已按组名自动处理：只要该组只命中「负样本」维度
> （`empty` / `arm_in_frame` / `hand_in_frame` / `ripple` / `debris` / `wall`），
> 采集结束就写会话级背景标记 `raw/<会话>/.background`，组装时它们以
> **「有图无标签的背景帧」**进入训练（ultralytics 记为 backgrounds）。
>
> 注意：**同一帧里既有袋子又有杂物时，袋子仍要标** —— 那属于正样本帧，不要标背景。

## 四、数量与分集（隔离纪律）

| 分集 | 来源 | 数量 | 隔离方式 |
|---|---|---|---|
| train | 第 1 批泳池帧 | 70% | `logical`：按采集批次/时间窗切分 |
| val | 第 1 批泳池帧 | 15% | 同上，**与 train 不同时间窗** |
| test | **另起一次采集**（重置水/灯/袋，重拍） | 15% | `physical`：独立目录，训练调参**全程不可触碰** |

- 同一批次的相邻帧（同一袋在同一位置连拍）**必须整组进同一个 split**，
  否则就是泄漏 —— 我们的画面是视频流，相邻帧几乎相同。
  做法：采集按**组**进行（每组一个会话目录），微调时用
  `finetune_pool.py --group-split` 按组整组切分（默认的逐帧洗牌会把同组相邻帧
  拆到 train/val 两侧）。
- 命名：`<日期>_<批次>_<位置>_<形态>_<序号>.jpg`，例如 `20261020_pool01_center_flat_0031.jpg`。
- 采集完按 `edge/grasp/data/manifests/template_pool_manifest.yaml` 补清单
  （字段 schema 与 `ml/datasets/manifests/README.md` §4 一致），`evidence_level: E2`。
  ⚠️ 池域清单放 `edge/grasp/data/manifests/`，**不要**塞进
  `ml/datasets/manifests/` —— 主链路的 `ml/tests/test_manifests.py` 断言该目录
  恰好解析出 train|val|test|blind 四份清单，多一份就会把它顶掉。

## 五、采集与标注的操作路径（现在全部可远程做）

1. 起作业台（开发机，远程模式）：见本仓库 `edge/grasp/web/server.py`，
   浏览器开 `http://127.0.0.1:8090`
2. 「1 · 采集」：先「手动点动 / 低头观测位」把臂摆好，再开始采集；
   每个位置/形态采完换下一组
3. 「2 · 标注台」：类别选 `plastic_bag`（袋子）；**负样本整张不标**（留作背景负样本）；
   池边的彩色物体可标 `buoy` 作显式负类
4. 标注完在「3 · 训练任务」起微调；「4 · 部署与回滚」部署；「5 · 标定与点动」示教放置点

> ⚠️ 采集时注意：USB 摄像头**一次只能被一个进程占用**（作业台与桥接层不要同时开）。

> **命令行等价路径**（不想开浏览器时）：
> `edge/grasp/tools/capture_pool.py` 按组分组建会话采集，自动写
> `data/capture/<批次>.json`（每组的条件与帧数，直接照抄进清单的 `confounders`）
> 与纯负样本组的背景标记；
> `edge/grasp/tools/finetune_pool.py --session <会话…> --group-split --deploy`
> 整组切分微调 → 留出集评估 → 导 ONNX → 原子部署，一条命令走完。

## 六、训练与评测口径

1. **底料**：公开数据预训练（`SC-FloatWaste` 已在库；TACO 用
   `edge/grasp/tools/build_taco_plastic.py` 建库，图像由 `fetch_taco_images.py`
   只下含袋框的那批 —— 522/1500 张，约 70MB 而不是全量原图 1.6GB）
   ★ **底料要「混」不要「接」**：实测先拿 TACO 真实照片预训练、再只用合成泳池域
   微调，会发生**灾难性遗忘** —— TACO val mAP50 从 0.397 掉到 0.014，真实域能力
   基本归零，底料等于白训。把底料用
   `finetune_pool.py --mix-dataset-yaml <底料 data.yaml>` **混进**微调（replay）
   才是对的：实测真实域保到 0.369（test 0.571），池域几乎不掉（P0.994/R0.925，
   纯合成版是 P1.000/R0.908）。**现场实拍微调时同理：把 TACO 一起混进去，
   别只喂泳池帧**，否则刚到手的真实域能力会在下一轮微调里再丢一次。
2. **无真机时的管线验证**（证据等级 **E1**）：合成泳池域帧可由
   `edge/grasp/tools/gen_pool_dataset.py` 生成（明亮青蓝池水 + 折光网纹 +
   彩色充气圈池壁 + 白色半透明袋四形态 + 彩色浮标 + **臂体/线缆/手入画负样本**），
   再用 `finetune_pool.py` 跑一遍 train→eval→export→deploy。
   它的作用是把管线真跑一遍、并给作业台一个能真推理的演示模型；
   **不得表述为现场精度**，真机到位后仍须按本规程自采重训。
3. **微调**：本规程产出的第一人称数据微调（640，与 `vision.input_size` 一致，
   否则 `cv2.dnn` 加载 ONNX 会报维度不匹配）；整组切分用 `--group-split`
4. **评测**：在**独立 test 集**上，按**精确率优先**（机械臂误抓代价高）
   —— 报 P/R 与 F1 最优点，并注明阈值；不要只报 mAP
5. **对外表述**：只写「受控泳池实验（E2）上的精度」，不得写「现场验证 / 真实海域」

## 七、验收口径（与主项目一致，不得含糊）

- `ok`（夹爪回读停滞 = 夹到东西）与 `placed`（松爪后袋子真的在料槽/回收位）
  **必须分开报**；`placed=False` 时 `review_result` 置 `recheck`
- 抓取点口径：检测框**中心**（`agent.grasp_point_mode: "center"`）
- 识别前必须先在**俯视观测位**识别（`agent.observe_look_down: true`），
  保证「锁定时看得见」=「伺服时也看得见」

## 八、检查清单（每次采集前过一遍）

- [ ] 水面已静置消泡
- [ ] 用的是白/半透明袋，池底已铺深色衬
- [ ] 相机离水面在 8~20cm 区间（实测，不靠目测）
- [ ] 臂在低头观测位（`pitch=-175`）
- [ ] 分辨率 640×480，未缩放
- [ ] 本轮每采 20~30 帧，就换一次位置/形态/光照
- [ ] 负样本已含「臂体入画」与「手入画」两类
- [ ] 纯负样本组已标背景（`capture_pool.py` 自动写 `.background`；手工采集需手动补，
      否则会被当成"尚未标注"整组丢掉）
- [ ] 相邻帧整组进同一 split（微调用 `--group-split`，不逐帧洗牌）
- [ ] 独立 test 集是**另起一次采集**，且已放到独立目录
