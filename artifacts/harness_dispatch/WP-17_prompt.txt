一、浏览器 E2E 的硬要求
==================================================

以 scripts/browser_acceptance.mjs 为主入口改造，保留原有 3 个 Agent 交互场景，但整个脚本必须按下面要求增强：

1. 登录必须走真实登录页与真实 POST /api/v1/auth/login，不允许用 localStorage 直接注入 token 伪造登录成功。登录后可以保存 storageState 供同一管理员上下文的业务页面复用。
2. 增加“未登录访问 /dashboard 必须跳转 /login”场景；不得只检查 URL，必须确认登录表单可见。
3. 登录 admin/admin123456 后，真实访问并检查以下页面：
   - /dashboard
   - /events
   - /tasks
   - /devices
   - /reports
   - /agents
   每页要求：
   - 页面根节点或稳定业务标识可见；
   - 至少等待其关键 API 请求完成并检查响应；
   - 关键 API 无 4xx/5xx（允许空列表，但页面必须正确显示空态而非崩溃）；
   - 捕获 pageerror/console error，出现真实运行时错误即失败；
   - 保存对应全页截图到 artifacts/browser-acceptance/，文件名稳定可找；
   - 原始 JSON 记录页面、路径、耗时、观察到的主要 API、业务可见证据。
4. 尽可能使用真实后端数据。只有以下情况允许 `page.route` 受控拦截，并必须在报告结果里标明 `mocked: true` 和原因：
   - 构造 Agent 活跃运行 / waiting_approval 这类当前数据库难以稳定生成的状态；
   - 构造特定前端异常态；
   - 不得拦截 Dashboard、Events、Tasks、Devices、Reports 的正常读取链路。
5. 增加真实 CSV 导出场景：
   - 工单 CSV：GET /api/v1/tasks/export；
   - 报表 CSV：GET /api/v1/reports/export；
   - 断言 HTTP 2xx、Content-Type 含 text/csv、文件非空、正文带 UTF-8 BOM、至少包含一个稳定表头；
   - 将两个导出文件保存到 artifacts/browser-acceptance/，报告记录字节数与 SHA256。
6. 增加 viewer 权限场景：
   - 真实登录 viewer/viewer123456；
   - 验证界面不暴露 admin/operator 写操作，或写按钮被禁用且有无权限提示；
   - 直接访问写接口应收到 403（选一个稳定写接口进行真实请求，不要修改业务数据）。
7. 增加 MQTT 降级但只读平台仍可用的场景：
   - 直接请求真实后端 GET /health，不用拦截；
   - 断言 dependencies 包含 redis/mqtt/database；
   - 当前无 broker 时，真实断言 mqtt 不是 ok、status 不是 ok；
   - 同时真实打开 /dashboard，确认页面仍可加载和读取业务 API；
   - 报告必须写明“MQTT 真实断开时只读能力可用；这不等于真实设备或网络压测”。
8. 报告结构至少包含：
   - generated_at
   - frontend_url / backend_url
   - evidence_level: "E1"
   - scope_note：明确真实做了什么、拦截了什么、不代表真实用户/设备/海域
   - results：每项含 name、passed、elapsed_ms、mocked、evidence
   - summary：total/passed/failed
   - observation：页面扫描到的 API 路径去重列表
9. 任一场景失败，进程退出码必须为 1；全部通过为 0。
10. 脚本应从 `PLAYWRIGHT_CORE_PATH` 加载 playwright-core；缺依赖时给出明确命令，不允许静默跳过关键场景。

二、受控故障演练包
==================================================

新增 scripts/fault_acceptance.py。它不是新的“真实故障”证据，而是把现有已实现的确定性故障恢复用例做成一键可复现的 E1 证据包。

1. 用 Python subprocess 调 pytest，逐组执行并解析结果，不得用字符串猜测成功：
   - 健康检查真实降级语义：backend/tests/test_health_degradation.py
   - ACK 启动恢复：backend/tests/test_ack_startup_recovery.py
   - 设备孪生 ACK 闭环与重复回放幂等：backend/tests/test_ack_twin_loopback.py
   - ACK 持久化/API 幂等（至少覆盖 backend/tests/test_mqtt_ack.py、test_task_ack_api.py、test_task_ack_persistence.py 中稳定子集）
   如果某组在仓库根目录无法工作，修正命令，不得直接删除该组。
2. 可选 live probe：
   - 若设置 `SEASIGHT_BACKEND_URL`，请求 GET /health；
   - 记录真实 status、dependencies、ack_recovery（字段可能因旧进程缺失，缺失要如实记录而不是伪造）；
   - live probe 结果与内部测试分组分开，不能混为同一证据等级。
3. 输出 artifacts/fault-acceptance/latest.json，包含：
   - generated_at
   - evidence_level: "E1"
   - runner
   - groups，每项含 name、command、returncode、parsed_summary、passed
   - live_probe（未配置时为 null）
   - scope_note：说明是受控测试，不代表真实 broker、公网、硬件或现场故障
   - summary
4. 所有内部测试组通过才返回 0；任一失败返回 1。
5. 终端输出要适合答辩现场展示：逐组 PASS/FAIL、通过数、证据文件路径。
